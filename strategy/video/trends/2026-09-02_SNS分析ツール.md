# SNS 分析・データ取得ツール比較（TikTok / YouTube Shorts / Instagram Reels）

調査日: 2026-09-02
調査方法: WebSearch / WebFetch のみ（アカウント登録・ログイン・課金・インストールは行っていない）
料金はすべて確認日 2026-09-02 時点。公式ページで確認できなかったものは「未確認」と明記し、第三者記事の値は「（第三者）」と付けた。

## 1. 結論

### 用途(1) 四半期の定点観測（自グループ＋競合5組のフォロワー数・投稿数・再生数）
- **入れるべきもの**: YouTube は **YouTube Data API v3**（公式・無料・1日1万ユニットで十分）。Instagram は **Instagram Graph API の Business Discovery**（公式・無料。ただし自分のプロアカウント＋Facebook ページ＋Meta 開発者アプリが要る）。TikTok は個人が使える公式 API がないので **Apify（TikTok Scraper, 無料枠 月$5）** を第一候補、**Bright Data（無料枠 月5,000レコード）** を第二候補にする。
- **要らないもの**: Exolyt / Pentos / Noxinfluencer / Tofu / コムニコなどの分析 SaaS（月1万〜10万円台で法人向け。6アカウント×年4回の数値取りには過剰）。TikTok Research API（日本の個人は申請資格なし）。
- **理由**: 取る数は「6アカウント×3媒体×年4回」で、どの無料枠にも余裕で収まる。既に Python で twitterapi.io を回している運用に、同じ形（スクリプト＋CSV）で足すのが最も安く、再現性がある。

### 用途(2) 定期的な流行調査（界隈で伸びている縦動画・音源・ハッシュタグ）
- **入れるべきもの**: **TikTok Creative Center**（公式・無料・地域=日本でトレンドのハッシュタグ・音源・クリエイター・動画が見られる）を軸に、キーワード／ハッシュタグ検索の上位動画は **Apify TikTok Scraper**（再生数・尺・音源メタが取れる）と **YouTube Data API の search.list**（1日100回、`videoDuration=short`）で補う。キーワードの季節性は **Google Trends**（無料、YouTube 検索・日本）。
- **要らないもの**: Kalodata（TikTok Shop＝物販向け）、Pentos Trends Pro（$99/月）、Shortimize（$99/月）。Instagram の Hashtag Search API（App Review で「Public Content Access」承認が必要、個人には現実的でない）。
- **理由**: 「上位動画の再生数・尺・音源」が取れれば足りる。Creative Center で界隈外の大きな流れを、スクレイパーで界隈内の具体動画を取る二段構えが、月数百円分の無料枠で回る。

### 用途(3) 自分の投稿の効果測定（視聴完了率・フォロワー外再生比率・プロフィール遷移）
- **入れるべきもの**: **外部ツールは不要**。TikTok Studio（視聴完了率「Watched full video」・平均視聴時間・リテンション・トラフィックソース(おすすめ比率)・新規フォロワー・プロフィール閲覧・新規/リピート視聴者）、YouTube Studio（Shorts の「Viewed vs swiped away」・平均視聴時間/率・新規/リピート視聴者・登録者増）、Instagram インサイト（視聴数・リーチのフォロワー/非フォロワー内訳・視聴時間・平均視聴時間・プロフィールアクセス・フォロー）で全部見える。
- **要らないもの**: Metricool / Buffer / Later 等の自アカウント分析ダッシュボード。1アカウントなら公式画面で足りる。
- **理由**: 欲しい3指標はすべて各媒体の公式アナリティクスにあり、外部ツールはその API を経由して同じ値を出しているだけ。必要なのはツールではなく「月1回、決まった表に転記する」運用（データ保持期間の制約があるため）。

| (2) 界隈の上位動画 | Apify TikTok Scraper でキーワード／ハッシュタグ検索（「地下アイドル」「ライブアイドル」「ファンカム」＋競合名、各 30 件）→ 再生数・尺・音源。YouTube は `search.list`（q, `videoDuration=short`, `order=viewCount`, `publishedAfter`=直近 90 日, `regionCode=JP`）→ `videos.list` で尺・再生数 | Apify 5〜8 クエリ × 30 = 150〜240 件 ≒ $0.6〜0.9。YouTube 10 クエリ = 10 回（枠 100/日） |
| (3) 自投稿 | TikTok Studio / YouTube Studio / Instagram インサイトから月 1 回転記（TikTok は PC 版で CSV） | 0 |

Apify の無料枠 $5 に対し、月の消費は $1〜2 で収まる。Bright Data の無料枠（5,000 レコード）はさらに余裕があるので、Apify の Actor が壊れたときの予備にする。

なぜ Apify を第一候補にするか: 単価表がプラン別に公開されていて見積もりが立つ、GUI で入力→スケジュール実行→CSV 出力まで完結する、Python クライアントがある、TikTok の Actor が音源メタ（曲名・オリジナル音源か）と尺を返す、の 4 点。Bright Data は無料枠が大きいが、非同期スナップショット方式で「取れるまで待つ」運用が要り、UI も英語の管理画面寄り。どちらも個人で使えるので、迷ったら両方登録して壊れていない方を使うで良い（登録は本調査では行っていない）。

なぜ Instagram を公式 API でやるか: Business Discovery は公式で無料、フォロワー数・投稿数・各投稿の view_count が取れる。ただし前提（自分のプロアカウント化、Facebook ページ連携、開発者アプリ作成）を一度組む手間があり、相手がプロアカウントでないと取れない。手間を避けるなら Apify Instagram Scraper（無料枠で十分）でも用途(1)は成立する。

### 案B: 月 2,000 円以内構成（案A ＋ 冗長化）

無料構成で機能は足りるので、有料分は「壊れたときの逃げ道」と「量の余裕」に使う。どれか 1 つで良い。

### 運用手順の概要

- **月 1 回（用途(2)(3)）**

  3. TikTok Studio / YouTube Studio / Instagram インサイトから、直近 30 日の自投稿の再生数・視聴完了率（TikTok: Watched full video、YouTube: 平均視聴率＋Viewed vs swiped away、IG: 視聴時間/平均視聴時間）・フォロワー外比率（TikTok: トラフィックソース For You％＋新規視聴者、IG: リーチの非フォロワー内訳、YouTube: 新規視聴者）・プロフィール遷移（TikTok/IG: プロフィール閲覧、YouTube: 登録者増で代替）を転記。TikTok は PC 版で CSV を落として保存。

## 4. 利用規約・法的な注意点

### 確認できたこと
- **TikTok 利用規約（日本語版）**は「本サービスから情報を収集するために自動化されたスクリプトを使用すること」を禁止している（第5条）。米国版も「robot, spider, crawler, scraper, or other automated means」による抽出を書面許可なしで禁止。TikTok は対スクレイピング対策を公式ブログで公表しており、Actor が壊れる原因になる。
- **YouTube 利用規約**は自動化された手段（ロボット、ボットネット、スクレイパー）でのアクセスを禁止し、例外は (a) 公開検索エンジンが robots.txt に従う場合、(b) 事前の書面許可、（米国版では (c) 適用法で許される場合）。robots.txt は /watch /channel /playlist を Disallow。**公式 API を使う限り問題ないが、API Services Developer Policies で「保存した API データは 30 日で更新または削除」**が原則。統計値（再生数・登録者数など）は追加ポリシー（derived-metrics-policy）で最長 36 か月保持でき、「チャンネル間の比較・履歴分析」が明示的に許容されている。
- **Instagram 利用規約**は「自動化された方法で情報を収集すること」を明示の許可なしで禁止（Meta の表現: "collecting information in an automated way without our express permission"）。公式 Graph API（Business Discovery / Insights）はこの許可の内側。Hashtag Search は App Review で「Instagram Public Content Access」承認が必要で、承認後も 30 ハッシュタグ/7 日の上限。
- **TikTok Research API** は日本の個人には資格がなく、商用利用も不可。
- **米国判例**: Meta v. Bright Data（N.D. Cal. 2024-01-23）はログアウト状態での公開データ収集は Meta の利用規約違反にならないと判断。X Corp. v. Bright Data（2024-05）は X の契約・不正流用の主張を著作権法の専占を理由に棄却。いずれも米国の地裁判断で、日本の裁判所を拘束しない。
- **日本法の一般論（弁護士解説の範囲）**: スクレイピング自体を直接禁じる法律はなく、問題になるのは (a) 著作権（情報解析目的の複製は著作権法 30 条の 4 / 47 条の 5 で一定範囲許容。ただしコンテンツ本体の保存・再公開は別）、(b) 利用規約違反（契約上の問題。アカウント停止や損害賠償請求の根拠になり得る）、(c) 過度なアクセスによる業務妨害、(d) 個人情報保護法（個人を識別できるデータの取扱い）。
- 実務上の線引きとして、本調査で扱う運用（公開されている数値のみ、月数百件、自分のアカウントでログインしない、集計値のみ保存、生データや個人情報を再公開しない）は、リスクを小さく保つ側に入る。ただしゼロではない。第三者スクレイパー（Apify / Bright Data 等）を使う場合、規約違反の当事者は主に事業者側になるが、取得データの利用者としての責任が残る可能性は否定できない。

### 確認できなかったこと
- 日本の裁判所が「ログアウト状態の公開データ収集」を利用規約違反として扱うかどうかの判例。
- Apify / Bright Data / ScrapeCreators が利用者に対して法的責任をどこまで負う（免責する）か（各社の利用規約は未読）。
- Instagram Graph API を「自分だけが使う開発モードのアプリ」で運用する場合に App Review が不要かどうか（ドキュメントに記載なし。Hashtag Search は必要と明記）。
- YouTube の 36 か月保持ポリシーが、フォームでの受け入れ手続きを要するか自動適用か。
- TikTok Creative Center の閲覧を手動で行う分には問題ないが、Apify の「TikTok Trends Scraper」（Creative Center 由来のデータ）を使う場合の規約上の位置づけ。

## 5. 参考記事（note / Bright Data 紹介）の評価

# 縦動画の流行調査手順（定点観測）

`prompts/collect/strategy_metrics.md`（X の四半期定点観測）と同じ考え方で、**縦動画の「型」の流行**を
同じ手順・同じ表形式で繰り返し観測する。結果は `trend_YYYY-MM-DD.md` として並べ、前回と比較する。

- **周期**: 月 1 回（型の流行は四半期より速く動く。数値の現状把握だけは四半期でよい）
- **第 1 回**: `02_調査_縦動画トレンドとノウハウ.md`（2026-09-02）。以降はこの手順の出力形式に揃える。
  第 1 回の教訓: **TikTok・X・YouTube のページ本体は WebFetch で取得できない**（JS 描画・402）。動画の尺・冒頭 1 秒・字幕量・個別再生数は
  検索だけでは埋まらず、Creative Center もログイン壁で未取得だった。**第 2 回からは「Claude Code の検索」と「手元のブラウザでの目視」を分業する**（下の実行手順）
- **実行者**: Claude Code（WebSearch / WebFetch）＋オーナー（手元のブラウザ・アプリで目視、30 分程度）

## 実行手順（毎回同じ）

1. Claude Code に下の実行プロンプトを渡し、検索で埋まる範囲（動画 URL の候補、先行事例、数値のスニペット）を先に埋めさせる
2. 出力の「伸びている型」表で `—` のままの列（尺・冒頭 1 秒・字幕量・再生数）を、**オーナーが手元のブラウザ／アプリで上位 10 本を実際に再生して転記**する
3. 計測 2（Creative Center）と計測 3 の TikTok 分は、アプリ／ブラウザで見た値を転記する（Claude Code は URL の準備まで）
4. 表が埋まったら Claude Code に「前回からの差分」を書かせ、`trend_YYYY-MM-DD.md` として保存する
- **恒久化するときの置き場**: `lollpop_docs/prompts/collect/video_trend.md`（手順）と `lollpop_docs/video/trends/`（結果）

## あなたの仕事は「計測」であって「提案」ではありません
- 評価や感想（「伸びている」「良い」）は書かない。観察した事実だけを表に入れる
- 確認できなかった項目は空欄にし、「確認できなかった項目」に回す。推測で埋めない
- 数値には必ず確認日時と URL を添える
- **第三者集計サイト（userlocal 等）の値は「出典: 第三者集計・未確認」と明記し、アカウントの紐付けも疑う。**
  第 1 回はこのサイトの値でアカウントとフォロワー数の両方を間違えた。アプリで裏が取れた値と混ぜて書かない

## 計測1: 伸びている型（上位 10〜20 本）
「地下アイドル」「ライブアイドル」「対バン」「特典会」「ファンカム」「推しカメラ」などの語と、
競合グループ名（ストロボグリッター・踊れ！神風・メリーパレード・戦国アニマル極楽浄土・AZの理由）、
先行例（iLiFE!・CANDY TUNE・FRUITS ZIPPER・Appare!・メリーパレード）で検索し、
直近 90 日に投稿されて再生数が多い動画を 10〜20 本挙げる。
各動画について、型（ファンカム / メンバー紹介 / 自己紹介リレー / あるある・ネタ / コール講座 /
振り真似 / 舞台裏 / 特典会風景 / 情報テロップ系 / その他）、尺、冒頭 1 秒に映るもの、
字幕量（なし / 要点 / 常時）、音源（原曲 / ライブラリ音源 / 流行音源 / ナレーション）、
投稿者種別（公式 / メンバー個人 / ファン）、再生数を記録する。

X のフォロワー数はこの調査では扱わない（twitterapi.io の定点観測 `strategy/metrics_YYYY-MM-DD.md` が正。検索スニペットの値は古いので使わない）。
- ろりぽっぷ公式: TikTok @lollipop_1116 / Instagram lollipop_official / YouTube（チャンネル有無を確認）
- メンバー個人 TikTok（`guide/link.md` が正。2026-09-02 時点の 5 人）:
  やぎくるみ **@lpop_kurumi（規模が大きいのはこちら。2026-09-02 実測 25.1 万）**・@kurumi_chandayo（489）／夏川茉夢 @omayu17／まう @mautan0127／松川愛美 @ami_matsukawa／愛月まな @manadayoooooooo。

  **フォロワー数だけでなく直近 5 本の平均再生数を必ず併記する**（@lpop_kurumi は 25.1 万フォロワーで直近 1,000〜2,600 再生。片方だけ見ると判断を誤る）
- 競合 5 組の公式（アカウントは検索して特定し、根拠をメモに残す。第 1 回時点で TikTok が未特定: 戦国アニマル極楽浄土・踊れ！神風・AZの理由）
- **曲の指標**: TikTok の音源ページで「ぽっぽ♪ポジティブ！！」の使用投稿数。**基準値 989 件（2026-09-02 実測）**。

## 結果の使い方（フォーマット定義への反映ルール）

1. 「前回からの差分」に**新しく現れた型**があれば、`05_フォーマット定義/` に `X<番号>_<名前>.md` を
   状態「試行中」で追加する。由来欄に `trend_YYYY-MM-DD.md 計測1 の何番` と書く
2. 試行中の型は、定義ファイルの「判定本数」まで投稿し、「自アカウントの投稿」表の値で採用／廃止を決める
3. 採用した型は ID を `N` または `E` に付け替えず、**そのまま `X` 番号で残す**（履歴の追跡を優先。対象層は定義ファイルの中で更新する）
4. 廃止した型はファイルを削除せず状態だけ「廃止」にする。再流行したら「試行中」に戻す
5. 数値の現状（計測3）は四半期ごとに `strategy/growth_strategy.md` の KPI 表へ転記する
   （現行の `strategy_metrics.md` に TikTok / YouTube / Instagram の列を足す提案は `01_縦動画戦略方針.md` に記載）

## ツールの使い分け

`03_調査_SNS分析ツール比較.md` の推奨（案A: 無料のみ構成）に従う。要点だけ再掲:

| 計測 | 手段 | 費用 | 備考 |
| --- | --- | --- | --- |
| 計測1 伸びている型 | まず WebSearch / 手元のブラウザで目視。量が要るなら Apify TikTok Scraper（キーワード検索・再生数・尺・音源メタ）＋ YouTube Data API `search.list`（`videoDuration=short`, `regionCode=JP`） | Apify 無料枠 $5/月のうち $1 弱、YouTube 無料 | **TikTok の規約は自動収集を禁止しているので、スクレイパーは「手動で足りないとき」に限る**（規約上グレー。詳細は調査 B の 4 節） |
| 計測2 流行音源・タグ | TikTok Creative Center（地域=日本・期間 30 日）を手動で転記。Google Trends（YouTube 検索）で季節性 | 無料 | 公式ツール。ログイン不要で閲覧可 |
| 計測3 数値の現状 | YouTube Data API v3（公式・無料）／Instagram は Graph API Business Discovery か Apify Instagram Scraper／TikTok は Apify TikTok Scraper（予備: Bright Data 無料枠 5,000 レコード、Social Blade 手動閲覧） | 四半期 $0.5 程度 | 6 アカウント × 3 媒体 × 年 4 回。既存の twitterapi.io と同じ「Python スクリプト＋CSV」の形に揃える |
| 計測4 自アカウント | TikTok Studio（視聴完了率・トラフィックソース・プロフィール閲覧）／YouTube Studio（Viewed vs swiped away）／Instagram インサイト（リーチのフォロワー外内訳） | 無料 | 外部ツール不要。TikTok は PC 版で CSV を落として保存（表示期間に上限があるため月 1 回転記） |

有料の分析 SaaS（Exolyt・Pentos・Tofu 等）は法人価格で過剰。Bright Data は Apify の予備。
ツールの登録・課金は本手順では行わない（実行前にオーナーが判断する）。

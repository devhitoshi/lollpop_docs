## G との関係（2026-09-04 追加）

**G「掲示板掛け合い」は F と同じ N-c 未認知層を狙う並走の型で、F はその対照群にあたる。**
選定基準（4 基準）・引用ルール・禁止事項・主指標は 2 型で共通にしてあり、**違うのは語り口・尺・素材構成・ループの本数だけ**。
こうしておくと、完了率が動いたときに「ネタが良かったのか、語り口が効いたのか」を分離できる。

**そのため F の仕様は G の判定が済むまで動かさない。**掛け合い・二重ループ・ライブ映像を F に取り込みたくなっても、
6 本ずつの実測が出るまでは待つ。動かすと比較にならない。

特に**名乗りの扱いは 2 型で正反対**にしてある（F = 名乗らない／G = 開示の瞬間に 1 回だけ名乗る）。
どちらが正しいかは仮説の段階では決めない。詳細は `G_掲示板掛け合い.md`。

## 型の仕様

| 項目 | 値 |
| --- | --- |
| 尺 | **20〜25 秒**（完了率が最も高い帯。TikTok は視聴完了率が新規リーチに効く） |
| 冒頭 1 秒 | **ギャップを問いの形で出す。オチは出さない。**名乗り・ロゴ・タイトルカードから始めない |
| 構成 | **0–3s フック（問い）／3–10s 状況（投稿スクショ＝本人の言葉）／10–18s 展開（自分の言葉の解説）／18–23s ペイオフ（オチ）** |
| 演出ルール | **8 秒以上おなじ絵を出さない**（離脱の主因）。1 本 1 エピソード。2 つ目のネタは別の動画にする |
| 名前の出し方 | **尺を使って名乗らない。**プロフィール・X・出典 URL はキャプションに回す。知らない人に名前を読み上げても判断材料にならず、その秒数はエピソードに使う方が効く（B が「曲名を字幕に入れない」としているのと同じ思想）。ただし**上帯に「ろりぽっぷ!!!!!!!／あだ名」を小さく常時表示**する — 切り抜き・転載で出所が消えるのを防ぐため |
| 字幕ルール | 常時・1 画面 15 字以内。**専門用語は必ず言い換える**（生誕→誕生日のライブ、対バン→何組か出るイベント、特典会→終わったあと話せる時間、手売り→本人が直接売る）。G と同じ扱い |
| 話速・行間 | **話速 1.3 倍・行間 0.15 秒**（F/G 共通、2026-09-07 決定。既定速度（1.0 倍）だと字幕を読み終わってから読み上げが続いて間延びするため。詳細は `G_掲示板掛け合い.md`「会話の密度と話速」） |
| 音源 | ライブラリ BGM ＋ VOICEVOX ナレーション。原曲は使わない。**話者は冥鳴ひまり**（2026-09-09 オーナー決定。クレジットは `VOICEVOX:冥鳴ひまり`。G は春日部つむぎ（語り）× 冥鳴ひまり（合いの手）で、F の語りと G の合いの手が同じ声になる） |
| 画角・比率 | 9:16、1080×1920。セーフゾーンは `projects/lollpop_video/src/safeArea.ts` の定数に従う |
| メッセージ | 1 本 1 つ。「この人、こういう人なんだ」が残ればよい。フォローを促す文言は動画内に入れない |
| キャプション・タグ | **台本と一緒に承認をもらう。**固定要素: 引用元の投稿 URL ／ メンバー名・あだ名・担当カラー ／ 公式 X `@lollipop_1116` ／ `#ろりぽっぷ` `#ライブアイドル` `#アイドル`（5 個以内。`#fyp` `#おすすめ` は付けない）／ 「VOICEVOX:話者名」のクレジット。**動画内で名乗らない分、情報はここに寄せる** |
| プラットフォーム差分 | TikTok が主。Instagram（Reels）は締めを「誰かに送りたくなる一行」に差し替える（Meta 公式: シェアが新規リーチに最も効く）。X は URL を先頭に置きキャプションを短く。**TikTok からダウンロードした透かし入りファイルを転載しない** |

## 選定基準（この型の要）

候補は **4 基準を全て満たすものだけ**を通す。1 つでも欠けたら落とす。

| # | 基準 | 判定 | 落ちる例 |
| --- | --- | --- | --- |
| 1 | **ギャップがあるか** | 「アイドルのイメージ」と「実際の姿」の落差を **1 文で書けるか**。書けなければ落とす | 「おはよう＋自撮り」＝落差ゼロ |
| 2 | **オープンループが作れるか** | 「え、どうなったの？」という問いに変換できるか | 告知だけの投稿は問いにならない |
| 3 | **ペイオフが具体的か** | オチを**一言・一行動で言い切れるか**。「楽しかった」で終わるものは落とす | 感想だけの投稿 |
| 4 | **予備知識が要らないか** | グループ名・曲名・専門用語を知らなくても通じるか。用語は言い換えられるか | 曲名の略称だけで成立する内輪ネタ |

**いいね数は選定に使わない。** `lollpop_data` の実投稿 458 件を調べたところ、いいね上位はほぼ「おはよう＋自撮り」だった。
これは既存ファンが顔を見たくて押しているもので、**新規への訴求とは相関しない**。参考値として表示はするが並び順には使わない。

### 基準を実データに当てた例

| --- | --- | --- | --- | --- | --- |
| 放水ライブ／濡れたあと全身撮るの忘れた | 客に水をかけまくるアイドル | 水をかけた後に後悔したことは？ | 自分の濡れた写真を撮り忘れた | 不要 | **採用** |

| おはてぃー🤍 ＋ 自撮り | なし | 立たない | なし | — | 落とす |

## 素材

| 項目 | 値 |
| --- | --- |
| 映像 | **メンバー本人の投稿のスクリーンショット**（出典を画面に残す）＋ 自分の言葉の解説。ユーザーが撮った写真があれば併用。スクショはユーザーが撮る（X はログインしないと表示されず、こちらから取得できない） |

## 引用の扱い

**メンバー本人の公開投稿に限り、出典を画面に明示して引用できる**（2026-09-03 改訂。それ以前は投稿原文の映像化を禁止していた）。

実務条件:

- 出典（アカウント名・投稿日）を**画面内に残す**。キャプションだけに書かない
- 投稿 URL をキャプションに置く
- **引用が主にならないよう、自分の言葉の解説を必ず添える**（スクショを並べただけの動画にしない）
- 削除・非公開になった投稿は使わない。公開が確認できたものだけ

**ファン（第三者）の投稿も、playbook 7.3 の作法に従えば引用できる**（2026-09-07 改訂。それ以前は「エゴサーチで集めた第三者の投稿は対象外」としていた）。
作法は playbook 7.3 の 7 か条（許諾済みアカウント優先／@handle を消さない／文言を変えない／引用部分を見た目で区別／自分の素材を主にする／ネガティブな反応は使わない／使ったら一言伝える）に従う。

## 禁止事項

テンプレートの共通項目を継承する。ただし「非公開データの投稿原文を映像化しない」は**メンバー本人の公開投稿に限り上記の条件つきで解除**。

型固有の追加:

- **「地下アイドル」と言わない**（メンバーに嫌がる人が多いため。ハッシュタグも不可）
- 本人が触れていない私生活・交友関係を推測して補わない。**投稿に書いてあることだけで組み立てる**
- ギャップを作るために本人を下げる表現をしない（「アイドルなのに〜」の言い方で貶めない）
- フォロー・登録を促す文言を動画内に入れない（キャプションで足りる）
- ファンの投稿を引用する場合は playbook 7.3 の作法（上記「引用の扱い」）を必ず守る。ネガティブな反応・比較・個人攻撃は使わない

## KPI と判定

| 項目 | 値 |
| --- | --- |
| 主指標 | **視聴完了率**（TikTok の新規リーチはここで決まる）。副指標: **平均視聴時間（絶対秒数）**、フォロワー外再生比率、プロフィール遷移数 |
| 判定本数 | 6 本 |
| 採用基準 | 6 本の中央値で視聴完了率が B・D を上回る。またはフォロワー外再生比率 80% 超が 2 本以上 |
| 廃止基準 | 6 本すべてで離脱が 3 秒以内に集中し、フックの型を 2 回変えても改善しない |

## 検証記録

投稿 **48 時間後**と **7 日後**に記録する。**3 本ごとに見直し**、効いたギャップの型とフックの文言を次に回す。

| 日付 | 動画 | ギャップの型 | フックの文言 | ペイオフの型 | 視聴完了率 | 平均視聴時間 | 離脱した秒 | フォロワー外比率 | プロフィール遷移 | メモ |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| | | | | | | | | | | |

**離脱した秒の読み方**: 3 秒に集中 → フックが弱い。10 秒前後 → 8 秒ルール違反（絵が変わっていない）。
18 秒以降 → ペイオフまで持っているので、オチの質だけの問題。

**この 4 基準は仮説であって確定ではない。**検証記録が溜まったら基準自体を書き換える。

## 毎日のワークフロー

```
① Claude が SNS トレンドを調べる（軽い当たり付け。下記の限界を参照）
② daily_pick.py で候補を出し、4 基準で 3〜5 件に絞る
③ ★ 台本＋キャプションを承認依頼 → ユーザーが 1 件選び、スクショを 1 枚撮る
④ VOICEVOX → Remotion → mp4
⑤ Google ドライブに保存
⑥ ★ ユーザーがスマホで確認 → 訂正があれば ④ に戻る
⑦ ★ 承認 → ユーザーが TikTok / Instagram / X に投稿
⑧ 48 時間後・7 日後に指標を記録（検証記録へ）
```

★ = ユーザーの承認が必須。飛ばして先に進まない。

**⑥ の訂正を安く回すために、台本は JSON、レイアウトは Remotion コンポーネントに分けてある。**
文言の直しは JSON を変えて再レンダリングするだけで済み、作り直しにならない。

### 毎日の調査の限界（先に書いておく）

**TikTok・X・YouTube の本体は WebFetch で取得できない**（JS 描画・402。`流行調査手順.md` 第 1 回の教訓）。

| 毎日できる | 毎日できない |
| --- | --- |
| WebSearch で直近のトレンド記事・話題の型・流行音源の言及を拾う | 個別動画の再生数・尺・冒頭 1 秒・字幕量 |
| 拾った型を 4 基準に当てて「今日はどの切り口が効きそうか」を書く | TikTok Creative Center の数値（ログイン壁） |
| ろりぽっぷ・競合の新規投稿の有無を確認する | アプリ内でしか見えないトレンド |

**毎日の調査は軽い当たり付けに留める。**数値の裏取りは月 1 の `流行調査手順.md`（オーナーが手元のブラウザで目視）が担う。

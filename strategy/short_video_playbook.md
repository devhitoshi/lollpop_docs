# ファンがショート動画で布教するための運用設計（2026年9月版）

ファン（非公式）の立場で、布教（知ってもらうこと）をショート動画（TikTok・Instagram リール・YouTube ショート）でやるための運用手順です。
個別の公演告知はしません（理由は 6.3）。動画の役目は「知ってもらう」ことと、X と TimeTree へ送ることです。
`strategy/growth_strategy.md` の施策2・3が**公式・メンバー側**の運用を想定しているのに対して、この文書は**ファン側**の運用を扱います。
両者は使える素材の範囲が違うので（対バンでは動画が指定曲のみ）、同じやり方は取れません。

事例の出どころは [`strategy/research_2026-09-05_ショート動画運用の事例.md`](./research_2026-09-05_ショート動画運用の事例.md)。
素材の在庫は `data/x/media_index_2026-08-01_2026-08-31.csv`、許諾の記録は `data/x/media_permissions.md`、
組み立ての道具は `.claude/skills/x-media-collect` です。

---

## 1. 結論を先に

1. **量で回さない。「型」で回す。** ファンが自由に動画を撮れるのは主催・単独ライブだけで、2026年1〜8月は月0〜5本・平均2.8本しかありません。毎日投稿は公式・メンバーの土俵です。ファン側は**月3回の現場で仕込んで、月10本前後に切り出す**設計にします。
2. **軸はろりぽっぷ単独。幅は「同じ現場に立つ共演者」まで。** 売れている他グループを混ぜてリーチを借りる形は、素材（撮影可否）とアルゴリズムの両方で割に合いません（6章）。
3. **1本ずつの告知はしない。恒常の導線に置き換える。** 公演は直近12ヶ月で月平均14.8本あり、告知は追いつきません。プロフィールと固定コメントを TimeTree と公式X（@lollipop_1116）に固定して、動画側は日付を持たない作りにします。
4. **X は動画の置き場にしない。** JASRAC の UGC 許諾サービス一覧に TikTok・YouTube・Instagram は載っていて、X は載っていません（2026-08-21 時点のページ、確認 2026-09-05）。動画本体は TikTok に置き、X は静止画とリンクで回すのが権利の面でも素直です。

## 2. 前提 — これは「非公式の運用」である

| 項目 | この運用の立場 |
| --- | --- |
| 誰の発信か | ファン個人。公式・運営ではない |
| 何のためか | 布教（認知）と、次の公演への導線 |
| 使える素材 | 自分で撮ったもの＋ `data/x/media_permissions.md` に「OK」の記録があるものだけ |
| 楽曲 | TikTok のアプリ内ライブラリにある公式音源を選ぶ（書き出しは無音） |
| クレジット | 全区間に焼き込む（オーナー方針・2026-09-02。`make_vertical.py` に外す引数はない） |

X ではパロディ・コメンタリー・ファン（PCF）アカウントについて、2025年4月以降、表示名の先頭に「fan」等を置くこと・
プロフィールに非公式である旨を書くこと・公式と同じアイコンやヘッダーを使わないことが求められています。
TikTok 側にも同じ趣旨の表記（プロフィール1行目に「非公式ファン運営」）を置きます。**公式と誤認されないことが、この運用の最低条件です。**

## 3. なぜショート動画か（数字だけ）

- 商品を知るきっかけになったコンテンツ形式は「ショート動画」が **69.8%** で最多（エクスクリエ調査、2026年7月、n=1,200）
- 推し活を始めたきっかけは「動画サイトで見た」27.2%、「SNSで見た」18.1%、「イベント・ライブで見た」14.4%（ネットエイジア調査、2026年3月、n=1,000）
- ろりぽっぷ側のファネル診断は「上細り」——来場・リピートは太く、認知だけが細い（`growth_strategy.md` 7章）
- 直近の実測では、初見らしき反応は月5件（`strategy/metrics_2026-09-02.md`）

つまり**受け皿は既にあって、上に流し込む管だけが無い**状態です。ショート動画はその管の中で一番安いものです。

## 4. 事例から抜き出した4つの型

事例の詳細と出典は調査メモにあります。ここでは運用に落とせる形だけ書きます。

### 型1: 権利をはっきりさせた側が、拡散量を取る

カバー（ホロライブ）は 2022年6月に切り抜きガイドラインを出し、「概要欄の冒頭に元動画の URL とタイトル」を条件に収益化まで認めました。
ANYCOLOR（にじさんじ）は 2025年5月に事前登録制へ改定。エンタメ事務所の NUM CREATION も「出典の明記・公式アカウントのメンション・文脈を歪めない編集」を条件に公開しています。
切り抜きが本体に効いた数字としては、ひろゆきのチャンネルが切り抜き出現の前後1年で登録者獲得 83,247名 → 772,000名（+827%）という集計があります（kamui tracker、2022年）。

→ **この運用への翻訳**: 許諾を記録で持つこと（`media_permissions.md`）は、面倒な手続きではなく**拡散の前提条件**。
記録がある素材だけが増えれば増えるほど、作れる本数が増えます。逆に記録の無い素材で1本作ると、運用ごと止まります。

### 型2: 「参加できる形」を先に見せた曲が伸びる

iLiFE! は曲の中にコールが組み込まれた構造で TikTok に広がり、2025年8月27日に日本武道館。会場ではスクリーンにコールとミックスを表示していました。

→ **この運用への翻訳**: 教えるのではなく、**参加している場そのものを映す**。
「客席が一緒に動いている画」が入った15秒は、コールの解説より強い。コール表（`songs/call_list.md`・26曲分）は、
現場に来た人・予習したい人が読む資料として置いたままにします（動画の型にはしない）。

### 型3: 出し惜しみしない

韓国のコンテンツ運用では番組本編の7〜8割を先に SNS へ出す設計が一般的（電通・Advertising Week Asia 2024 レポート）。
BE:FIRST「Boom Boom Back」は TikTok 関連動画の総再生3億回超。

→ **この運用への翻訳**: 「現場に来ないと分からない」を売りにしない。サビもコールもセトリも先に出す。
ろりぽっぷは**主催ライブが動画全編撮影可・掲載可**なので、この型を取れる数少ないグループです。

### 型4: 再生数はゴールではなく入口

地下アイドルの TikTok 運用の解説では、投稿を「認知／楽曲／メンバー／信頼／行動」の5役に分け、
①動画内にグループ名を表示②投稿文で次の行動を案内③プロフィールにライブ情報、の3段階の導線を必ず置くこととされています。
セレッソ大阪の UGC 施策も「いいね→リポスト→リプライ→引用→投稿」と段階を踏む設計でした。

→ **この運用への翻訳**: 1本ごとに「見た人に次にしてほしいこと」を1つだけ書く。全部の動画で「ライブ来て」と言わない。

## 6. アカウント設計 — 名前と、扱う範囲

ここがこの運用の一番の分かれ道です。**先に「何のアカウントか」を決めないと、名前も番組表も決まりません。**

### 6.1 扱う範囲 — ろりぽっぷ単独か、他グループを混ぜるか

**結論: ろりぽっぷ単独を軸にする。幅は「同じ現場に立つ共演者」まで。売れている他グループを混ぜてリーチを借りる形は取らない。**
目安は 8:2 で、他グループは**素材を作らず、言及と引用でだけ触れる**。

理由は3つあります。

| # | 理由 | 中身 |
| --- | --- | --- |
| 1 | **素材が手に入らない** | 撮影可否はグループ・事務所ごとの方針で、**大手・有名になるほど不可に寄る**。国内最大級の TOKYO IDOL FESTIVAL 2026 ですら、カメラマーク付きの出演者に限りスマートフォンでの**静止画のみ**可で、**動画の撮影・録音は禁止**（TIF2026 公式、2026年7月27日掲載）。つまり「売れているグループを混ぜる」は、映像のないテキストとリアクションだけの型になり、主力にならない |
| 2 | **アルゴリズムが軸を見る** | 2026年の TikTok は「関連する周辺トピックへの展開は許容するが、**まったく無関係なジャンルへの突然の変更はリスクが高い**」とされ、ジャンルを絞るほどリーチが安定するという説明が運用各社で共通している（アンドゼン、2026年3月26日公開・3月31日更新。確度・中の実務知） |
| 3 | **回遊しないフォロワーは評価を下げる** | 動画を見た人がプロフィールへ飛び、他の動画も見てフォローする——この回遊がアカウント全体の評価を押し上げる仕組みとされる（同上）。他グループ目当てで来た人はろりぽっぷの回で離脱するので、フォロワー数だけ増えて中身が薄くなる |

**ただし「幅ゼロ」も違います。** 効くのは大手ではなく**対バンの共演者**です。手元の実測でも、2026年8月に伸びたファン投稿の上位2件は共演者アカウント（@SD_KIKO0804）の投稿で、いいね87・表示2,430、いいね68・表示3,115 でした（`strategy/metrics_2026-09-02.md`）。
**外からの言及は、いま実際に共演者経由で来ています。** 対バン文化では出演枠も動員も相互の関係で決まるので（`growth_strategy.md` 4章①）、ここへの目配りは互恵になります。

やり方は、素材を借りずに済む形に限ります。

- 共演者の投稿を**引用**する（自分で素材を作らない＝許諾が要らない）
- 対バン当日に「今日は◯◯と同じ現場」と**言及**する（相手のハンドルを正しく書く）
- 相手の素材を使いたくなったら、先に許諾を取って `data/x/media_permissions.md` に記録する（順序を逆にしない）

### 検討して取らなかった案 — ジャンルの看板を借りる（2026-09-07）

「可愛い女の子紹介チャンネルの体裁にして、ろりぽっぷの紹介を強める」案を検討しました。**取りません。** 理由は3つです。

| # | 理由 | 中身 |
| --- | --- | --- |
| 1 | **素材の壁は看板を変えても消えない** | 他グループの子を紹介するには写真・動画が要る。他人が撮ったものには撮影者の著作権があり、被写体には肖像権・パブリシティ権がある。無断使用は削除要求や損害賠償・差止請求の対象になりうる（弁護士・弁理士による一般解説、確認日 2026-09-07）。事務所によってはファンに向けて画像の利用を控えるよう明示的にお願いを出している（例: ワタナベエンターテインメント「SNS利用に関する大切なお願い」）。**成立させるには毎回許諾を取るしかなく、月8〜10本の運用では回らない** |
| 2 | **看板で釣る利得が小さい** | TikTok は動画ごとに配信され（フォロワーへの先行テスト→反応が良ければ外部拡散）、分配を決めるのは**1本ごとのフック**であってアカウントの看板ではない。「別ジャンルの体裁」で得られるものは想像より小さく、ジャンルが混ざるぶんリーチはむしろ不安定になる（6.1 の理由2・3） |
| 3 | **失うものが大きい** | 釣られたと感じた人の不満は、非公式アカウントではなく**ろりぽっぷ本体に跳ね返る**（名指しで宣伝している以上、切り離せない）。対バン相手を素材扱いすれば共演者とその場のファンとの関係も損ない、ブッキングは動員と関係で決まる世界（`growth_strategy.md` 4章①）。さらに「可愛い女の子紹介」という枠組み自体が、被写体の意向や運営の許諾範囲（**使途は未確認**。11章）と衝突しやすい |

**ただし「入口を広げたい」という狙い自体は正しい。** 「ろりぽっぷ」だけでは検索の母数が小さいのは事実です。
広げるものを**顔ではなくトピック**に置き換えます——**地下アイドルの現場そのものを入口にして、例が全部ろりぽっぷになる**形なら、
素材は自前で足りるし、誰も騙されません。シリーズの候補:

- **「はじめての対バン」** — 何が起きる場所なのか、どう過ごすのか
- **「500円で行けるライブがある」** — ワンコイン公演＋初回写メ券無料（`guide/rules.md`。事実として強い）
- **「現場で撮っていいもの・だめなもの」** — 撮影ルールの話。可否はグループごとに違い、需要がある
- **「チェキって何？」** — 相場（1,500円）と流れ、初めての人が不安に思うところ

そのうえで他グループを本当に出したいなら、**体裁ではなく実際にやります**: 共演者紹介の枠を月1本、
**先に本人へ連絡して許諾を取り**、`media_permissions.md` に記録してから紹介する。相手も拡散するので、借りるのではなく交換になります。

### 6.2 名前 — 満たすべき条件と、そのまま使える案

名前が満たすべきことは4つです。

1. **検索で当たる。** 「ろりぽっぷ」は名称が衝突していて、YouTube で検索すると別団体（名古屋の同名アイドル、仙台の幼稚園）が上位に出ます（`growth_strategy.md` 2章）。表示名にグループ名（**!は7個**）と、アイドルだと分かる語を入れる
2. **非公式だと一目で分かる。** X はファン・パロディ・コメンタリー（PCF）アカウントに、表示名の先頭へ「fan」等を置くこと・プロフィールに非公式である旨を書くこと・公式と同じアイコンやヘッダーを使わないことを求めている（2025年4月以降）
3. **何をする人か分かる。** 「記録」「切り抜き」のように動詞が見える語を入れる。**メディア名（速報・ニュース）にはしない**——速報は公式の役割と衝突するし、間違えたときの責任の重さが変わる
4. **全プラットフォームで同じハンドルにする。** TikTok・Instagram・YouTube・X を同時に取る

そのまま使える案:

| 項目 | 案 | 備考 |
| --- | --- | --- |
| ハンドル（4サービス共通） | `lollipop_fanrec` | 予備: `lollipop_rec_fan` / `roripopu_rec`。4つとも空いているかを先に確認する |
| TikTok・Instagram・YouTube の表示名 | **ろりぽっぷ!!!!!!! 非公式ファン記録** | 「記録」を「切り抜き」に替えてもよい（どちらも中身が分かる語） |
| X の表示名 | **fan ろりぽっぷ!!!!!!! 非公式ファン記録** | PCF の要件で先頭に `fan`。あわせて PCF ラベルを設定する |
| プロフィール1行目 | 東京のアイドル「ろりぽっぷ!!!!!!!」を追いかけているファンの非公式アカウントです。公式は @lollipop_1116 | 誤認防止と、検索語（アイドル・グループ名）を同時に満たす |
| プロフィール2行目＋リンク | 公演の予定は TimeTree に全部あります → TimeTree のURL | 導線（6.3） |
| アイコン | 自分で撮った写真、または自作の図 | **公式のロゴ・アー写は使わない** |

避ける名前:

- `lollipop_official_fan` のように **official を含む形**、公式ハンドル（`lollipop_1116`）に似た数字
- 「ろりぽっぷ速報」「ろりぽっぷ情報局」のような**メディア風**（公式の役割と衝突する）
- 個人名だけ・愛称だけ（検索に当たらない。グループ名が入っていないと1の条件を落とす）

### 6.3 告知はしない。導線を固定する

公演は**直近12ヶ月で月平均14.8本**（直近6ヶ月は15.5本、最多は2026年5月の22本。`events/data_event.csv`）。
1本ずつ告知しても追いつかないうえ、日付入りの動画は数日で賞味期限が切れて**在庫にならない**——だから告知はしません（オーナー判断・2026-09-07）。
代わりに、**動画側は日付を持たず、導線を3か所に固定します**。

| 置き場 | 書くこと | 直せるか |
| --- | --- | --- |
| プロフィールのリンク1段目 | **TimeTree（公演カレンダー）に直結** | いつでも |
| 全動画の固定コメント | 「予定は TimeTree に全部あります／公式は @lollipop_1116」 | いつでも（動画は使い回すので、日付はここに書かない） |
| 動画の最後1〜2秒 | 「予定は全部 TimeTree」＋グループ名 | 焼き込みなので**日付を入れない** |

そのうえで、**「月15本ある」こと自体を売りにします**。「いつ行っても会える」は、月1〜2本のグループには書けない一行です。
日付の羅列ではなく**選び方**（初めてならどの公演か、ワンコインはどれか）を月1本だけ出す型を、番組表の D に置きました。

## 7. 運用設計

### 7.1 置き場（プラットフォームの役割分担）

| 場所 | 役割 | 出すもの |
| --- | --- | --- |
| **TikTok** | 本拠地。新規に届く唯一の場所 | 全部。アプリ内で公式音源を選ぶ |
| Instagram リール | 既にフォローしている層への再接触 | TikTok と同じ動画（ロゴ無しで書き出したもの） |
| YouTube ショート | 検索で後から見つかる在庫 | 同上。タイトルを検索語で書く |
| **X** | 拡散と導線の起点。**動画本体は置かない** | 静止画＋ショート動画へのリンク。公演当日の実況・共演者への言及 |

X を動画の置き場にしないのは、JASRAC と利用許諾契約のある UGC サービスの一覧に TikTok・YouTube・Instagram は載っていて、
X は載っていないためです（JASRAC、ページ更新 2026-08-21・確認 2026-09-05）。
ライブ映像には楽曲の著作権が乗るので、包括契約のある場所に本体を置き、X からはリンクで送るのが素直な設計です。
※これは権利まわりの整理であって法律の助言ではありません。気になる範囲は運営に確認します（11章）。

### 7.2 番組表 — 4つの型

1本ごとに役割を1つだけ持たせます。**どれも日付を焼き込まない**（在庫として使い回すため）。

| # | 型 | 尺 | 中身 | 素材 | 本数の目安 |
| --- | --- | --- | --- | --- | --- |
| **A** | **現場の熱**（主力） | 15〜20秒 | 主催日の映像を9:16に。上に曲名、下に会場。客席が一緒に動いている画を優先 | 主催日の動画（月3日の仕込み） | 月5〜6本 |
| **B** | はじめての人向け | 45〜60秒 | 「1分でわかるろりぽっぷ!!!!!!!」。5人・曲・入口の軽さ（ワンコイン＋初回写メ無料＋撮影OK）。**入口を広げる回はトピック側から入る**（「はじめての対バン」「500円で行けるライブ」など。6.1 のシリーズ候補） | 写真の連結で作れる | 固定投稿1本＋月1本 |
| **C** | 記録もの | 20〜30秒 | 「326公演のセトリを数えたら」「今月いちばん歌われた曲」「2年で会場はどう変わったか」 | このリポジトリの集計。**素材ゼロで作れる** | 月2〜3本 |
| **D** | 今月の入り方 | 20〜30秒 | 告知ではなく**選び方**。「今月は15本ある。初めてならこの種類の公演」。日付は読み上げず「予定は全部 TimeTree」で締める | 写真＋テロップ | 月1本 |

**C は素材の在庫を消費しません。** 動画素材が枯れる月でも投稿が止まらないのはこの型のおかげです。
そして C（326公演の記録・セトリの集計）は、**このリポジトリを持っている人にしか作れない**という意味で、いちばん真似されにくい型でもあります。

落とした型と、その理由（オーナー判断・2026-09-07）:

- **コール講座** — ライブはコールをしなくても成立する。教えるより先に、来てもらうほうが順番として前
- **個別の公演告知** — 月15本前後あってキリがなく、日付入りの動画は在庫にならない。導線の固定（6.3）に置き換えた

### 7.3 まわし方（月のリズム）

```
主催・単独ライブの日（月3日前後）
  └ 撮る: 縦持ちで、1曲まるごと × 2〜3曲。サビと、客席が動いている画は必ず縦で押さえる
      翌日        → A（現場の熱）を1本
      以降2週間で → A の別カットを4〜5本に小分け（曲ごと・メンバーごと）

対バンの日（月10〜14日）
  └ 撮る: 写真。動画は指定曲のみ
      → 共演者への言及・引用はこの日に（素材は借りない）
      → 写真は B・D の素材と、X 側の投稿に回す

現場が無い日
  └ C（記録もの）を作り置き。月末に D（今月の入り方）を1本
```

目安は**週2本＋公演翌日1本＝月10本前後**。毎日投稿は狙いません。
運用解説でも「本数より継続性」が共通の推奨で、TikTok は投稿直後に数百人規模へ先に配信して反応を見る仕組みとされています（確度・中の実務知）。
続けられる本数を決めて、そこを下回らないことのほうが効きます。

### 7.4 1本ごとのチェックリスト

作るたびにこれを通します（`make_vertical.py` で組み立てる場合も同じ）。

- [ ] **最初の2秒**に「何が起きるか」が出ているか（曲名・会場名・数字を先に出す）
- [ ] **グループ名が画面に出ているか**（「ろりぽっぷ!!!!!!!」。!は7個）
- [ ] **声・テロップ・キャプションの三層**に検索語が入っているか（グループ名／曲名／会場名。TikTok は音声認識と画面内テキストを拾うとされる）
- [ ] **クレジット**が全区間に入っているか（`manifest.csv` の出典から。自分で撮ったものは `"credit": "撮影: 自分"`）
- [ ] **無音で書き出した**か（TikTok のアプリ内で公式音源を選ぶため）
- [ ] **非公式である表記**（プロフィール1行目。動画側にも「ファンによる非公式の投稿です」を小さく）
- [ ] **日付を焼き込んでいないか**（在庫として使い回すため。日付は固定コメントにだけ書く）
- [ ] 固定コメントに**「予定は TimeTree に全部あります／公式は @lollipop_1116」**（動画は使い回すので、後から直せる場所に置く）

### 7.5 導線（見た人が次にどこへ行くか）

```
ショート動画（TikTok）
   └ 固定コメント: 「予定は TimeTree に全部あります／公式は @lollipop_1116」
   └ プロフィール1行目: 「ろりぽっぷ!!!!!!!（東京のアイドル）を追いかけているファンの非公式アカウント」
        ├ リンク1段目: TimeTree（公演カレンダー）… 次の現場へ最短
        ├ リンク2段目: 公式 lit.link（https://lit.link/roripopu1116）… 公式X・配信・ショップ
        └ 固定投稿: B（1分でわかる）
```

リンクの1段目を lit.link ではなく **TimeTree** にするのは、「次にいつ会えるか」が最短で分かる場所だからです。
lit.link は公式の入口をまとめた2段目に置きます（公式X のフォローはそこから取る）。

殺し文句は事実だけで足ります——**「500円＋ドリンク代で、ライブを見て、メンバーと写真を撮るところまで行ける」**
（ワンコイン公演＋公式Xフォローで初回写メ券無料、`guide/rules.md`）。

### 7.6 素材の増やし方

| 打ち手 | 効き方 | 手順 |
| --- | --- | --- |
| **自分で縦持ちで撮る** | 一番強い。許諾も要らない | 主催日に1曲まるごと縦で。月3日を外さない |
| @Hamakun4 に許諾を依頼 | 他人素材の27%が一度に開く | `media_permissions.md` の「個別の許諾」に追記してからでないと落とせない |
| 上位20アカウントまで広げる | 他人素材の73%（上位10人で58%） | 同上。1人ずつ記録する |
| @Bf1pR（しゃけさん） | TikTok・YouTube に精力的。要所で | 都度依頼（記録は「都度」のまま） |

主力の型 A（現場の熱）は**主催日に自分で縦持ちで撮った素材**でほぼ賄えます。
他人の許諾を広げるのは「撮り逃した日を埋める」ためで、順番としては自分の撮影が先です。

## 8. やらないこと

- **公式に見えるようにしない**（アイコン・ヘッダーの流用、名前の紛らわしい表記、公式の告知文の丸写し）
- **記録に無い素材を使わない**（「今回だけ」を作らない。`fetch_media.py` は記録の無いアカウントを落とせない作りにしてある）
- **対バン日の動画を上げない**（指定曲以外は撮影不可。曲の指定は現物の告知で確認する）
- **クレジットを外さない**（出典が引けない素材は spec に `"credit"` を書かないと処理が止まる）
- **他のグループを下げる比較をしない**（対バン文化圏ではブッキングに跳ね返る）
- **売れているグループの映像でリーチを借りない**（素材の許諾が無く、アカウントの軸もぶれる。6.1）
- **メディアを名乗らない・速報をやらない**（公式の役割と衝突し、間違えたときの責任が変わる）
- **卒業したメンバーの卒業後の活動・私生活に触れない**、運営の意図・体調・人間関係を推測しない（`CLAUDE.md`）
- **疲れる設計にしない**（金銭・時間の疲弊は離脱理由の筆頭。月10本を上限とみなす）

## 11. 運営・メンバーに確認したいこと（未解決）

`data/x/media_permissions.md` の「確認しておきたい項目」と同じ内容です。**回答が来たら permissions.md の列にして、動画側は読むだけにします**（個別条件を記憶でなく記録で扱うため）。

1. **使途** — ファンによる告知・周知の縦型動画に限るのか、他にも使えるのか
2. **改変** — 切り出し・トリミング・テロップ・BGM 差し替えの可否
3. **クレジット** — 表記の要否と書き方（ハッシュタグ・メンションの指定）。いまは `make_vertical.py` 側で文面を決め打ちしている
4. **音源** — 楽曲を動画に乗せてよいか（TikTok のアプリ内ライブラリにあることは確認済み）
5. **期限** — 期間の定めがあるか、取り消しの連絡先
6. **対バンの指定曲** — 動画撮影が可能な曲を、ファンが事前に知れる形で出してもらえるか（主力の型 A の素材が、月3日ぶんから一気に増える）

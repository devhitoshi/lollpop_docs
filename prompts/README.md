# プロンプト管理

このディレクトリでは、アイドルグループ「ろりぽっぷ!!!!!!!」に関するLLM用プロンプトを管理しています。
用途別に2系統あります。

## 1. データ収集・記事執筆プロンプト

**収集と執筆を分離**しています。Grok は X 検索と画像OCRという代替不能な能力にだけ使い、
文章の質は Claude 側で握ります。こうしておくと、**文体を直すたびに Grok で取り直す必要がなくなります**。

```
[Grok] x_collect.md  ──→  構造化された事実データ
                              │
                              ├─→ [Claude] style_ai_poppar.md + write_weekly.md  ──→ 週刊note
                              └─→ [Claude] style_ai_poppar.md + write_monthly.md ──→ 月刊note
```

### Grok に投げるもの

| ファイル | 用途 |
|---|---|
| `x_collect.md` | 指定期間のXの動きを**事実データとして**収集する（週刊・月刊で共通） |
| `event_get.md` | 公式Xのライブ後投稿からセトリを抽出し、`data_event.csv` に追記する |

**使い方**
1. プロンプト内の `[開始日]` `[終了日]`（`event_get.md` は `[ここにJSONを貼る]`）を実際の値に置換する
2. Grok で**新規チャット**を開き、モデルを**「エキスパート」**にする
   （「ファスト」では X 検索が浅く、精度が落ちます）
3. プロンプト全文を貼り付けて送信する（長文なのでクリップボード経由が確実）
4. 1回＝1チャットにする。前の指示を引きずらせないため

**日付の置換とチャンク分割は自動化してあります。** 手で書き換えなくて構いません。

```bash
python3 .agent/scripts/prepare_collect.py --month 2026-08
```

半月境界で自動的に割り、チャンクごとに置換済みの `x_collect.md` と、母集団JSONを差し込んだ
`event_get.md` を `work/collect/` 以下に生成します。母集団（出演イベント一覧）は
`data_timetree.csv` に持っているので、TimeTree を毎回見に行く必要はありません。
新しい公演が増えたときだけ `update_timetree.py` でエクスポートを取り込みます。返ってきた出力を各チャンクの
`response.md` / `response.csv` として保存すれば、結合も自動でできます。

```bash
python3 .agent/scripts/merge_collect.py  --period 20260801-20260831   # 収集データを1本に結合
python3 .agent/scripts/merge_setlist.py  --period 20260801-20260831   # セトリCSVを data_event.csv へ
```

一連の流れは `skills/note_article/SKILL.md` にまとめてあります。

### Claude に渡すもの

| ファイル | 用途 |
|---|---|
| `style_ai_poppar.md` | 書き手「AIぽっぱー」の文体定義（週刊・月刊で共通） |
| `write_weekly.md` | 週刊記事の構成（**既にグループを知っている人**向け） |
| `write_monthly.md` | 月刊記事の構成（**グループを知らない人**向け。オタク度を一段下げる） |

**Grok にはこれらを渡さないでください。** 収集プロンプトに文体指示が混ざると、
記事の体裁で出力されてしまい、事実の抜けが見えなくなります。

### 共通の方針
- **確認できなかったことは書かない。** 推測で埋めさせない
- **曲名・イベント名は投稿どおりの表記を保つ**（`!` の数、`☆`/`★`、`〜`/`～` を正規化しない）
- 他人のポストは長文引用せず、要旨＋リンクにする
- 卒業したメンバーの卒業後の活動・私生活には踏み込まない
- 出典リスト・予定表・編集メモは**素の口調**で書く（感情を混ぜない）

## 2. LLMなりきりプロンプト

各メンバーになりきってLLMが対話するためのプロンプトです。

- `common_rules.md`: 全メンバー共通の振る舞い、禁止事項、世界観設定
- `aduki_mana.md` / `yagi_kurumi.md` / `natsukawa_mayu.md` / `matsukawa_ami.md` / `mau.md`: 現メンバー
- `himea_asaka.md` / `ichihana_natsumi.md`: 元メンバー

### 使い方
1. `common_rules.md` の内容をシステムプロンプトとして入力
2. 対象メンバーの `.md` ファイルの内容をキャラクター設定として入力

## 管理ルール
- メンバーのプロフィール情報（誕生日、出身地など）は、ルートディレクトリの `members.md` と整合性を保つこと
- 性格や口調の描写は、公式SNSやライブでの発言に基づいた、ファンが親しみを感じるレベルを目指すこと
- 現体制は5人（愛月まな / やぎくるみ / 夏川茉夢 / 松川愛美 / まう）。メンバー構成が変わったら全ファイルを見直すこと

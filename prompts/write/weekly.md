# 週刊まとめ記事の構成

`prompts/collect/x_collect.md` で収集した事実データから、note 記事を書くときの構成。
**文体は `prompts/write/style_ai_poppar.md` に従う。** Claude 側で使う。

## 読者

**すでにろりぽっぷを知っている人**。現場に通っている人、Xでフォローしている人が「今週なにがあったか」を追いつくために読む。

- グループの基本説明・メンバー紹介は**不要**。書かない。
- 「セトリ」「特典会」「対バン」「動員」「チェキ」「無銭」「ワンマン」「生誕祭」は**注釈なしでそのまま使う**。

## 構成

```markdown
# ろりぽっぷ!!!!!!! 週刊まとめ（[開始日] 〜 [終了日]）

（リード文：3〜5行。その週を一言でどう受け止めたか。
　軸になる出来事が1つあるなら、ここで名指しする）

## 今週のライブ
（日付順。1公演ごとに小見出しを立てる: `### 10/24（土）イベント名／会場`（太字の行にしない。目次に出ないため）。
　**時間・料金・セトリは箇条書きで淡々と。** そのあとに地の文。段落は120字まで、引用は1段落に2つまで（`style_ai_poppar.md`「構成の目安」）。
　同日に複数公演がある場合は分ける。ライブが無かった週は「今週はライブなし」と1行。
　セトリの箇条書きの直後に、その公演の公式ライブ後投稿の URL を単独行で置く）

## 初披露・新曲・アナウンス
（新曲、音源配信、グッズ、イベント告知。無ければ節ごと省略。告知の投稿を1本だけ埋め込む）

## メンバーの動き
（その週に動きがあったメンバーだけ。1人ごとに小見出し `### まう`。名前のあとに絵文字は付けない（`style_ai_poppar.md`）。埋め込みは1人1本まで。
　**濃淡を付ける**（2026-10-27 オーナー決定）: その週に山があった1〜2人は長く書いてよい。ほかは2〜3文の短信と埋め込み1本。
　全員を同じ形・同じ量で並べると単調になる。誰を長くしたかと理由は編集メモに書き、同じ人に毎週寄っていないかも見る）

## 現場の反応
（3〜6件。「誰が・何に対して・どう反応したか」を1〜2文。
　伸びていたポストは数字も添える。埋め込むのは共演者・主催など公の立場の投稿だけ）

## 来週の予定
（**素の口調で。** 箇条書き（note は表が使えない）。日付／イベント名／会場／チケット情報。
　再来週以降の予定も、地の文で並べず箇条書きにする）

## 出典
（**素の口調で。** note に載せるのは主なものだけ（2026-10-27 オーナー決定）:
　公式の告知・タイムテーブル、セトリの根拠（`events/data_event.csv` の時点）、本文で埋め込んでいない投稿のうち事実の根拠になったもの。
　全件は編集メモの後ろの「出典（全件）」へ）

---

編集メモ（note には載せない）
（確認できなかった項目・判断に迷った点・濃淡の理由）

出典（全件）
（参照したポストの URL 一覧。日付順。引用の裏取り用）
```

大見出し（`##`）の前には `---`（区切り線）を置いてよい。`md2note.py` が note の区切り線にする。

## 目次

note に貼るときは、リード文の後ろ（`## 今週のライブ` の前）に note の目次を入れる（2026-10-14 オーナー指示。月刊・単発も同じ）。
原稿の Markdown には書かない（note の目次は編集画面の機能で、見出しから自動で作られる）。入れ方は `.claude/skills/note-publish` の「6.5 目次を入れる」。

## 埋め込み（X の投稿）の置き方

note は URL を単独行に貼ると埋め込みカードになる。**本文が文字だけで続くのを切るために使う**（2026-09-10 決定、2026-10-02 に入れ直し）。
投稿を埋め込めば、写真は投稿の中に出る（写真を保存して載せる場合の扱いは `style_ai_poppar.md`）。

- **1記事あたり 6〜8 本。** それ以上は note の表示が重くなり、読む速度も落ちる。
- **URL は単独行にして、前後を空行で挟む。** 箇条書きの途中に入れるとリストが分断されるので、
  箇条書きの外（節の終わり、または段落の切れ目）に置く。
- **節ごとの配分**: 今週のライブ＝公演ごとに公式のライブ後投稿を1本、初披露・新曲・アナウンス＝告知を1本、
  メンバーの動き＝1人1本まで、現場の反応＝1本。
- **他人（ファン）の投稿は本文に文面を転記するだけにして、埋め込みは共演者・主催など公の立場の投稿にとどめる。**
  埋め込みは相手のアカウントを記事の一部として大きく見せる行為なので、個人のファンの投稿では扱いが重い。
- **出典の全件は編集メモの後ろの「出典（全件）」に残す。** note に載せる「## 出典」は主なものだけ（2026-10-27〜。スマホで7〜10画面あったため）。埋め込みは抜粋、出典（全件）は裏取り用、と役割が違う。
- 本数は `article-review` の機械チェック（`EMBED`）が数える。出典節の URL は数に入れない。

## 記事の後ろに、`---` で区切って編集メモ

- 確認できなかった項目
- 判断に迷った点

**素の口調で。** これらは note には載せない。

## 週の軸を1つ決める

事実を並べるだけでは読み物にならない。収集データを読んで、**その週を貫く出来事を1つ選び**、リード文で名指しして、記事全体をそこに向けて構成する。

例：新曲の初披露があった週なら「新曲が来た週」、体制変更後の初ライブなら「新体制が動き出した週」。
該当が無い週は無理に作らず、淡々と並べてよい。

# x_ugc_probe.py の使い方（検証用・1回きり）

`work/x収集ルートの検討.md` の「提案する次の一手」を実行するためのスクリプト。
**移行のためのものではない。** 「1クエリ10件の壁」が実害だったのかを、$0で確かめるだけ。

> **Claude Code のリモート環境からは実行できない。**
> `api.twitterapi.io` も `docs.twitterapi.io` もネットワークポリシーで 403（CONNECT拒否）。
> 手元のマシンで動かして、結果をこちらに貼る。

## 準備

1. リポジトリのルートに `.env` を作り、ダッシュボードのAPIキーを1行だけ書く

   ```
   TWITTERAPI_IO_KEY=（ここにキー）
   ```

   `.env` は `.gitignore` 済み。**キーをチャットに貼らない。**

2. Python 3 があれば依存パッケージは不要（標準ライブラリのみ）

## 実行

**まず疎通確認だけ**（1コール、$0.0002程度）。キーが通るかと、レスポンス形状の確認。

```bash
python3 work/x_ugc_probe.py \
  --check-user lollipop_1116 \
  --query 'from:lollipop_1116 since:2026-08-30 until:2026-09-02' \
  --max-tweets 20
```

ここで返るフォロワー数を `strategy/metrics_2026-09-01.md` の **1,385** と比べる。
一致すればGrokの数値は信用できる。大きく違えば、それ自体が別の発見になる。

**本題**（`strategy_metrics.md` の計測3-1 と同じクエリ・直近30日）。

```bash
python3 work/x_ugc_probe.py --max-tweets 400 --query \
'("ろりぽっぷ" OR "ろりぽ" OR @lollipop_1116) -from:lollipop_1116 -from:kurumi_lpop -from:mayu_lpop -from:mau_lpop -from:ami_lpop -from:mana_lpop since:2026-08-02 until:2026-09-02'
```

最大400件で約$0.06、0.2 QPS なので最大2分弱。実行前に見積もりを出して確認を求める。

## 結果の読み方

| 総件数 | 意味 | 次にやること |
| --- | --- | --- |
| 20〜30件 | Grokの「下限20件」はほぼ実数だった。10件の壁は実害なし | **現状維持で確定。**検討終了 |
| 100件以上 | `growth_strategy.md` のKPIベースラインが実態より大幅に低い | 併用案（案B）に進む価値あり |

ノイズ（レンタルサーバー「ロリポップ!」等）は**除去していない生の件数**なので、
100件を超えた場合は `work/probe_raw.jsonl` を目視で何割がノイズか確かめること。
そこが案Bで自前で書くことになる部分の重さの目安になる。

「`--max-tweets` に達して打ち切りました」と出たら、実数はもっと多い。
上限を上げて再実行すれば取得済みはスキップされる（中断・再開対応）。

## 未検証な点

- **検索エンドポイント `/twitter/tweet/advanced_search` とパラメータ名 `query` は未確認。**
  引き継ぎ文書の記載をそのまま使っている。404 が出たら `docs.twitterapi.io/llms.txt` を見て
  `--search-path` / `--query-param` で上書きする
- ベースURL `https://api.twitterapi.io` と認証ヘッダ `x-api-key`、
  `/twitter/user/info?userName=` はダッシュボードのcURL例で確認済み
- 単価（$0.15/1,000ツイート、$1=100,000クレジット）は引き継ぎ文書の記載。
  表示される概算コストもこの前提。**実際の消費はダッシュボードの残高で突き合わせること**
- 残高取得APIは未検証なので叩いていない。残高はダッシュボードで見る

## 守っていること

引き継ぎ文書の禁止事項に対応する。

- `--max-tweets` は必須（デフォルトなし）。省略するとエラーで止まる
- 実行前に推定コストと推定所要時間を表示し、確認を求める（`--yes` で省略可）
- APIキーはコードに書かず `.env` から読む。`.env` は `.gitignore` 済み
- 生JSONをそのまま JSONL に保存。分析軸を変えても再取得は不要
- 逐次処理（5秒/コール）。並列化はしない
- 429/5xx はジッタ付き指数バックオフでリトライ
- 取得済みIDを保存済みJSONLから復元し、再実行時はスキップ
- クレジットの購入・自動チャージ設定は一切しない

## 終わったら

このスクリプトは検証が済んだら役目を終える。

- **現状維持で確定した場合**: `work/` ごと削除し、結論だけ `work/x収集ルートの検討.md` に追記して
  `strategy/` か `prompts/` へ運び出す
- **案Bに進む場合**: ページング・リトライ・重複排除・再開の部分は `fetch.py` に流用できる。
  収集対象を7アカウントの `from:` 検索に変えて `prompts/collect/x_collect.md` の出力形式に
  整形する処理を足す

# セッション引き継ぎ

このリポジトリは、セッションをまたいで同じ人（と次の Claude）が作業を続ける。
引き継ぎの正は **各シリーズ README の「未解決（次のセッションへ）」節** と **CLAUDE.md の「（進行中）」セクション**。
チャットの要約は次のセッションに残らないので、ファイルに書くことがすべて。

## 手順

1. **現状を集める**

   ```bash
   bash .claude/skills/session-handoff/scripts/handoff_status.sh
   ```

   ブランチ・未コミット・origin/main との差分・work/ の中身・各 README の未解決・CLAUDE.md の進行中・集計の不足月・取得済み X 投稿を一覧する。

2. **「未解決」節を更新する**（該当するシリーズだけ）

   - 今回解決した項目は、消さずに `~~取り消し線~~ → 結果（YYYY-MM-DD）` の形にする（既存の書き方に合わせる。履歴として残す）
   - まだ残っている項目は、状況が変わっていれば本文を書き換える（「あみてん・まうは未取得」→「まう取得済み、あみてん未取得」など）
   - 今回新しく分かった未解決を追加する。**次のセッションが最初に読んで動けるように、何が・どこまで・次に何をすればよいか** を1〜2文で
   - 記事一覧の表（ファイル名・期間・備考）に新しい記事を足す

3. **CLAUDE.md の進行中セクションを更新する**

   「済（YYYY年M月時点）」「待ち」「未解決」の行を現状に合わせる。長くしない。詳細は各 README に書き、CLAUDE.md からはリンクする。

4. **work/ を片付ける**

   `work/` は空が正常。残っているファイルは、恒久化するならドメインへ運び出し（表は `work/README.md`）、不要なら削除する。
   `work/x_fetch/` の取得データは `.gitignore` 済みで、ローカルに残してよい（他人の著作物なのでコミットしない）。

5. **X の取得データを退避する**（このセッションで x-account-fetch / x-egosearch を使ったとき）

   ```bash
   python3 .claude/skills/x-data-sync/scripts/sync_x_data.py push -m "<何を取ったか>"
   ```

   `work/x_fetch/*.jsonl` を非公開リポジトリ `lollpop_data` に圧縮して push する。判定ファイル（`data/x/`）は次の手順で lollpop_docs に commit する。

6. **コミットして push する**

   - コミットメッセージは既存の流儀に合わせる（日本語・何をしたかが1行で分かる。例:「週刊8/25-8/31号に「メンバーの動き」を追記し、抜けていた8/29公演を発見・追加」）
   - `git push -u origin <ブランチ>`。記事系の PR は作成後そのままマージしてよい（オーナー方針）。マージ後は作業ブランチを origin/main に揃え直す

7. **チャットに短い引き継ぎを書く**

   次のセッションのために、以下を各1〜3行で。ファイルに書いた内容の要約でよい。

   - 今回やったこと
   - 未解決（ファイルのどこに書いたか）
   - 次のセッションが最初にやること

## やらないこと

- 未解決の項目を「たぶん済んだ」で消さない。確認していないものは残す
- 引き継ぎのために新しいメモファイルを作らない（置き場は README と CLAUDE.md に決まっている。増やすと次の人が探せない）
- 取得した X 投稿の生データや `.env` をコミットしない（hook が止めるが、頼らない）

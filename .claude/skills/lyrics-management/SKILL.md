# 歌詞ドキュメントの作成・管理

## 保存先とファイル名

- 保存先: `songs/lyrics/`
- ファイル名: `[曲名].md`（曲名は公式表記のまま。`!` の数や `☆`/`★` を正規化しない）

## 手順

1. **歌詞を受け取る**
   ユーザーから画像（OCRで読み取る）またはテキストで歌詞が提供される。

2. **構成（セクション）を起こす**
   歌詞の流れから、イントロ／Aメロ／Bメロ／サビ／間奏／ブリッジ／Cメロ／落ちサビ／ラスサビ／アウトロ などを判定する。
   既存曲の構成は `songs/call_list.md` と `songs/lyrics/` の既存ファイルを参照する。

3. **クレジットを取得する**
   `guide/link.md` にある各配信サイト（TuneCore、Apple Music など）のリンクを開き、
   **作詞・作曲・レコーディングエンジニア**の情報を取得する。取れなかった項目は書かない。

4. **Markdown を組み立てる**

   ```markdown
   # 曲名

   ## 構成名
   ### 歌詞
   （歌詞本文）

   （構成ごとに繰り返し）

   ## 作詞 作曲
   - 作詞：
   - 作曲：
   - レコーディングエンジニア：
   ```

5. **保存し、レビューを依頼する**
   `songs/lyrics/[曲名].md` に保存したあと、構成名の付け方や歌詞の細部をユーザーに確認してもらう。

## 参照するファイル

| パス | 内容 |
| --- | --- |
| `guide/link.md` | 公式配信サイトのリンク（クレジットの取得元） |
| `songs/楽曲一覧.md` | 曲名の正表記・リリース情報 |
| `songs/call_list.md` | 既存曲の構成とコール |
| `songs/lyrics/` | 保存先。既存ファイルが書式の見本 |

## 注意

- 歌詞は聞き取り・OCRの誤りが残りやすい。**推測で補完せず**、読み取れなかった箇所はユーザーに確認する。
- クレジット末尾の見出しは `## 作詞 作曲` に揃える
  （`主人公.md` と `始まりの宴!!!!!!!.md` は `## クレジット` になっており、揃っていない）。

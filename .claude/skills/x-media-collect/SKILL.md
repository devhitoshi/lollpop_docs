# 縦型動画の素材索引

告知・周知を縦型動画でやるための、素材探し（手順1〜4）・取得（手順5）・組み立て（手順6）。
**索引に載るのはメタデータだけで、他人の素材は許諾を記録した分しか手元に来ない。**
使える素材かどうかは、下の「素材の3つの層」で判断する。

## 素材の3つの層（`guide/rules.md` の撮影ルールに基づく）

| 層 | 使えるか | 根拠 |
| --- | --- | --- |
| **自分で撮ったもの** | 使える。**これが主力** | 主催・単独ライブは「静止画、動画全編『○』」「動画、静止画の掲載は可能です。その際ハッシュタグやメンションのご協力お願いします」。対バンは静止画が全編可、**動画は指定曲のみ** |
| **公式・メンバーの投稿** | 運営に確認してから | グループ・事務所の著作物。ファンの告知に使うなら一声かけるのが筋。掲載歓迎の文脈があるので話は通りやすい |
| **他のファンの投稿** | 本人の許諾が要る | 撮影者に著作権がある。索引で相手を特定して、個別に依頼する |

X の `allow_download_status`（索引の `dl_flag`）は **X 上で保存ボタンが出るかどうか**であって、利用許諾ではない。混同しない。

## 手順

1. **索引を作る**

   ```bash
   python3 .claude/skills/x-media-collect/scripts/build_media_index.py --since 2026-08-01 --until 2026-08-31
   ```

   `data/x/media_index_<since>_<until>.csv` ができる（追跡する。URL と数値だけで画像は含まない）。
   取得データが無ければ先に `x-account-fetch` / `x-egosearch`、消えていれば `x-data-sync pull`。

2. **縦型の候補を絞る**

   ```bash
   python3 ... --orientation 縦 --type video --source 公式・メンバー
   ```

   `orientation` は元画像の縦横比から。縦型（9:16）にそのまま載る素材が見つかる。
   横型しかない見せ場は、切り出し（センター寄せ or 被写体追従）が要るので手間が別に発生する。

3. **撮影ルールの列で仕分ける**

   `撮影ルール` が「主催」の日の素材は、動画も全編撮影可・掲載可の日のもの。自分で撮った分ならそのまま使える。
   「対バン」の日の動画は指定曲のみなので、その曲だったかを確認する。**公演名からの推定なので、現物の告知で裏を取る。**

4. **許諾を取る・記録する**

   他人の素材を使うなら、`author` と `post_url` から本人に依頼する。もらえたら `data/x/media_permissions.md` の
   「個別の許諾」表に **`@handle` と可否 `OK`** で追記する（口頭やDMの記憶に頼らない）。
   索引の上位アカウントから当たると効率がいい（2026年8月の判定済みデータでは上位10人で 58%、上位20人で 73%）。

5. **許諾済みの分だけ落とす**

   ```bash
   python3 .claude/skills/x-media-collect/scripts/fetch_media.py --index data/x/media_index_<期間>.csv --dry-run
   python3 ... --index <csv> --orientation 縦 --type video
   ```

   `media_permissions.md` で「OK」のアカウント（＋公式が OK と記録されていれば公式）だけを
   `work/x_media/` に落とす。**記録に無いアカウントはコマンドラインで指定しても落とせない**
   （「今回だけ」で記録の無い素材が混ざらないように、許諾の記録を唯一の判断基準にしている）。
   使いたい素材の撮影者が記録に無ければ、先に許諾を取って permissions.md に足す。

   `work/x_media/manifest.csv` にファイルと出典（投稿URL・撮影者・公演）の対応が残る。**クレジット表記に使う。**
   `work/x_media/` は `.gitignore` 済み。許諾済みでも他人の著作物なので、リポジトリに入れない・再配布しない。

   **容量に注意。** 動画は 4K が多く、1本 300MB 近くになる。2026年8月の許諾済み456件を全部落とすと約 12.5GB
   （うち動画が 12.2GB、写真は 175MB）。必ず `--dry-run` で概算を見てから実行する。
   既定で `--max-total-mb 2000` の歯止めがあり、超えたら打ち切る（同じコマンドで再実行すると続きから落とす）。

   現実的な進め方:

   ```bash
   # 写真は軽いのでまとめて（縦219件で約175MB）
   python3 ... --index <csv> --orientation 縦 --type photo
   # 動画は使うものを索引で決めてから、日付や撮影者で絞って落とす
   python3 ... --index <csv> --type video --source 公式 --limit 5
   ```

6. **縦型に組み立てる**

   構成を JSON に書いて渡す。1区間＝1素材で、順につないで 1080x1920 の mp4 を書き出す。

   ```bash
   python3 .claude/skills/x-media-collect/scripts/make_vertical.py --spec work/vertical_spec.json
   ```

   ```json
   {
     "out": "work/x_media/vertical_2026-08.mp4",
     "segments": [
       {"file": "work/x_media/....mp4", "start": 3, "duration": 12,
        "top": "2026.8.26\n単独ライブ Vol.18",
        "bottom": "新曲「夏色ラムネ」お披露目\n中野坂上SUB TOKYO"},
       {"file": "work/x_media/....jpg", "duration": 4,
        "top": "次に会えるのは", "bottom": "9/20（日）単独ライブ Vol.19"}
     ]
   }
   ```

   - 画像の区間は `duration` 必須。動画は `start` で頭出しする
   - `top` / `bottom` は `\n` で複数行。上に「日付・公演名」、下に「曲・場所・次の予定」が読みやすい
   - 横の映像は**切り取らず**、幅 1080 で中央に置く。上下の余白は同じ映像をぼかして敷き、
     その上に半透明の黒帯（高さ430px）とテロップを重ねる。黒帯だけの画面より見栄えがして、被写体も切れない
   - 音は各動画区間のものを使う。`"mute": true` で無音にできる。
     **TikTok に上げるならアプリ内の公式音源を選ぶので、無音で書き出しておく**（手順の「音」を参照）
   - 素材を決める前に、動画の中身を見る。`ffmpeg -ss <秒> -i <file> -vframes 1 <png>` を数点撮って
     並べると、どこが見せ場か・公式のタイトルカードが入っているかが分かる

   出典は `work/x_media/manifest.csv`。公開するときはクレジットを添える。
   書き出したファイルも他人の素材を含むので `work/`（.gitignore 済み）に置き、リポジトリに入れない。

## 縦型動画に向く素材の条件

- **縦（9:16）**。横型を切ると被写体が切れる。ライブ撮影は最初から縦で撮る
- **15〜60秒**。1曲まるごとではなく、サビ・コール・振りの見せ場だけ
- **画質**。素材の動画は 4K（3840x2160）が31本と多い。縦型動画の書き出しは 1080x1920 で足りるので、
  編集の入力としては過剰。落とすときは本数を絞る（容量の話は手順5）
- **音**。ろりぽっぷの楽曲は TikTok のアプリ内ライブラリにある（2026-09-02 オーナー確認）。
  **アプリ内で公式音源を選ぶ形にする。** 自前の音源ファイルを乗せるのは別の話になる
- **顔が寄っている**。特典会のチェキ・写メは縦型で顔が近く、告知のサムネイルに向く（`guide/rules.md`「特典会中に撮影したチェキは、SNS等へアップしていただいて問題ございません」）

## 横動画の使い方（縦型に載せる）

素材の動画はほとんどが横向き（2026年8月の判定済みデータでは、縦型の動画は6件だけ）。
**横のまま 9:16 の中央に置き、上下の余白にテロップを入れる**構成にすれば、切り出さずに使える。
上に「何のライブか・日付」、下に「曲名・コール・次の予定」を置くと、音を出さずに見る人にも伝わる。

- 被写体を切らずに済む。ライブ映像は引きで撮られていることが多いので、無理にズームして切るより見やすい
- 上下の帯はグループの色を使う（`design.md` の `primary` #d6006e ／ `surface-blush` #fbe7f0）
- 顔を大きく見せたい箇所だけ、縦の写真（判定済みデータでは縦の写真が多数）を差し込む
- それでも**自分で縦で撮った素材はいちばん強い**。主催・単独は動画全編可・掲載可なので、次の単独は縦持ちで臨む

## やらないこと

- 他人の投稿の画像・動画を一括ダウンロードしない。索引で候補を絞り、許諾を取ってから個別に受け取る
- 索引に画像・動画そのものを入れない（`data/x/` は追跡するので、他人の著作物を置かない）
- `dl_flag` を利用許諾の根拠にしない
- 書き出した動画をリポジトリに入れない（素材と同じく他人の著作物を含む）

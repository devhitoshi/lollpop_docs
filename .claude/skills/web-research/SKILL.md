# Web 調査（戦略・市場・競合）

`strategy/growth_strategy.md` は「出典付きの事実」と「推定・言説」を分けて書くことで信用を保っている。
このスキルは、その材料を同じ規律で集めるための手順。調査結果は**文書に混ぜる前に、調査メモとして残す**。

## 置き場と形式

- 調査メモ: `strategy/research_YYYY-MM-DD_<題名>.md`（題名は日本語でよい。例 `research_2026-09-02_競合フェス出演状況.md`）
- 戦略文書への反映は別の作業。メモを読んで `growth_strategy.md` の該当節を直し、「付録: 主要参照元」に出典を足す

メモの構成（この見出しをそのまま使う）:

```markdown
# 調査メモ: <題名>（<YYYY-MM-DD> 実施）

## 問い
（何を知りたくて調べたか。1〜3行）

## 分かったこと（出典あり）
- <事実>（<媒体名>、<公開日または確認日>、URL）

## 推定・言説（出典が弱い、または一次情報でない）
- <内容>（根拠: …。確度: 高/中/低）

## 分からなかったこと
- <探したが見つからなかったもの。どこを探したか>

## 戦略文書への示唆
- <growth_strategy.md のどの節に、何を反映するか>

## 検索の記録
- <使ったクエリ／見たページ。同じ調査を繰り返さないため>
```

## 手順

1. **問いを1行で書く。** 「競合5組の直近フェス出演」のように、答えが表になる粒度まで絞る。広い問いは複数のメモに分ける
2. **一次情報を優先する順番で探す。** 公式サイト・公式 X → 主催者・会場の告知 → 業界メディア（ガルポ！、IDOL REPORT、Real Sound、日経クロストレンド等） → PR TIMES などのプレスリリース・調査会社 → まとめサイト・個人ブログ（言説扱い）
3. **WebSearch で当たりを付け、WebFetch で本文を読む。** 検索結果のスニペットだけで書かない。数字は必ず本文で確認し、「いつ時点の値か」を添える
4. **届かないサイトは記録して次へ。** リモート環境ではネットワークポリシーで到達できないドメインがある（linkco.re など）。到達できなかった URL は「分からなかったこと」に書き、ユーザーにスクリーンショットや本文の貼り付けを頼む
5. **事実と推定を分けて書く。** 出典が一次情報なら「分かったこと」、二次情報や推計なら「推定・言説」に確度付きで。迷ったら推定側に置く
6. **競合・他グループの扱い。** 事実（フォロワー数、会場規模、出演フェス）だけを書き、評価・優劣・下げる表現は書かない。個人（メンバー）の私生活・体調・人間関係には触れない
7. **反映するときは、文書側の「最終更新」と付録の参照元を同時に直す。** 調査メモへのリンクを残す

## やらないこと

- 検索結果の要約だけで数字を書く（本文未確認の数字は載せない）
- 出典の無い「業界ではこう言われている」を事実の節に書く
- 同じ問いを別メモで何度も調べ直す（先に `strategy/research_*.md` を grep する）
- X の投稿を根拠にした反応集計（それは x-egosearch と strategy-metrics の担当）

## 関連

- 定点観測（フォロワー数・UGC・公式の発信量）は `.claude/skills/strategy-metrics`。数値の時系列はそちらに集める
- 図表が要るときは内蔵の `dataviz` スキルと `design.md` の色トークン（`chart-*`）を使う

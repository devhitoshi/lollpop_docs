# 曲調データの作成・管理

歌詞（`songs/lyrics/`）と対になる、音の側のデータを作る。
歌詞考察記事（`articles/歌詞考察/`）で曲調に触れるための材料になる。

## 前提

- 音源が `audio/` にあること。入手方法は [`audio/README.md`](../../../audio/README.md) を参照。
  音源が無い場合は、ユーザーに購入をお願いする以外に進める道はない。**推測で数値を書かない。**
- librosa が入っていること。入っていなければ次を実行する。

  ```bash
  python3 -m pip install -r .claude/skills/music-analysis/scripts/requirements.txt
  ```

## 手順

1. **解析対象を確認する**

   ```bash
   ls audio/
   ```

2. **解析する**

   `audio/` の音源をまとめて:

   ```bash
   python3 .claude/skills/music-analysis/scripts/analyze_audio.py --all
   ```

   1曲だけ:

   ```bash
   python3 .claude/skills/music-analysis/scripts/analyze_audio.py audio/主人公.flac
   ```

   セクションの切れ方が歌詞の構成と合わないときは、分割数を指定して取り直す:

   ```bash
   python3 .claude/skills/music-analysis/scripts/analyze_audio.py audio/主人公.flac --sections 12
   ```

3. **歌詞の構成と突き合わせる**

   `songs/analysis/[曲名].md` のセクション表には、Aメロ・サビといった名前が付いていない。
   `songs/lyrics/[曲名].md` の構成と時間順に対応させて、どのセクションがサビかを読む。
   相対音量と密度が跳ね上がっている区間がサビであることが多い。

   対応が明らかに取れない（セクション数が構成と大きくずれる）場合は、
   `--sections` を歌詞の構成の数に合わせて取り直す。

4. **結果を伝える**

   BPM・キー・サビの持ち上がり幅など、記事に使えそうな点を挙げてユーザーに確認してもらう。

## 入出力

| パス | 役割 |
| --- | --- |
| `audio/[曲名].flac` など | 入力。購入した音源（リポジトリには入らない） |
| `songs/lyrics/[曲名].md` | 入力。構成の名前を対応させるために読む |
| `songs/analysis/[曲名].md` | 出力。1曲分の曲調データ |
| `songs/analysis/song_features.csv` | 出力。全曲比較用（BPM・キー・尺・ダイナミクスレンジ） |

## 数値の読み方

| 項目 | 意味 |
| --- | --- |
| BPM | テンポ。**倍・半分に振れることがある**（168 と 84 など） |
| キー | 12音の分布からの推定。**平行調と入れ替わることがある**（C major と A minor など） |
| 相対音量 | 曲中でいちばん大きいセクションを 0 dB とした相対値。サビの持ち上がり方 |
| 明るさ | スペクトル重心。高いほど高音成分が多く、抜けが良い |
| 密度 | 1秒あたりの音の立ち上がり数。高いほど手数が多い |
| ダイナミクスレンジ | 曲全体の音量の振れ幅。小さいほど終始詰まった音圧 |

## 注意

- **BPM とキーは推定値**。記事に書くときは断定を避けるか、耳で確かめてから書く。
  特にキーは平行調と入れ替わりやすい（A minor の曲が C major と出る）。
- セクション境界は音色と和音の変化から機械的に割ったもので、**楽曲構成の正解ではない**。
  歌詞の構成と突き合わせて解釈する工程を飛ばさない。
- **音源ファイルを絶対にコミットしない。** `.gitignore` で除外済みだが、
  `git add -f` などで無理に追加しないこと。ステム分離した wav も同じ。
- スクリプトは自分でリポジトリルートに `chdir` せず、`__file__` からの相対でパスを解決する。
  スクリプトを移動した場合は冒頭の `project_root` の階層数を直すこと。

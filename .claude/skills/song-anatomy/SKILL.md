# 曲の読み解き図（解剖図）

1 曲を楽器ごとに分けて時間で追い、**音で起きていること（事実）と、そこからの読み（考察）を分けて見せる図**を作る。
2026-10-02 に「シーソーゲーム」「ろりぽっぷ!!!!!!!」の 2 曲で型を確かめた。見本は
`songs/analysis/anatomy/シーソーゲーム/読み解き図.png`。

図は「データの 1 つの見せ方」。取れたデータは全部 `songs/analysis/anatomy/[曲名]/` に残し、記事・動画・MV から読めるようにする
（項目の説明は [`songs/analysis/anatomy/README.md`](../../../songs/analysis/anatomy/README.md)）。

## 前提

- 音源が `audio/[曲名].m4a` にある（入手は [`audio/README.md`](../../../audio/README.md)）。歌詞が `songs/lyrics/[曲名].md` にある
- 曲の印象が `songs/analysis/song_character.md` にある（題と導入文の根拠に使う。無ければ先に `music-analysis`）
- ffmpeg が入っている
- **専用の Python 環境**（初回だけ。数分）。いつもの Python に入れると torch の版がぶつかるので分ける

  ```bash
  python -m venv .claude/skills/song-anatomy/.venv
  .claude/skills/song-anatomy/.venv/Scripts/python -m pip install torch==2.5.1 torchaudio==2.5.1 --index-url https://download.pytorch.org/whl/cpu
  .claude/skills/song-anatomy/.venv/Scripts/python -m pip install -r .claude/skills/song-anatomy/scripts/requirements.txt
  ```

  図を作るだけ（手順 D）なら専用環境も音源も要らない。いつもの Python と Playwright で動く。
  クラウドの環境では、先に `bash resources/install_capture_font.sh` と `pip install playwright`（`CLAUDE.md` 実行環境の注意）。

以下、`VPY=.claude/skills/song-anatomy/.venv/Scripts/python`、`S=.claude/skills/song-anatomy/scripts` と書く。
Windows では `PYTHONUTF8=1` を付けて実行する。

## 手順 A: データを作る（機械。1 曲 5〜6 分）

```bash
$VPY $S/separate.py [曲名]    # 4 つの音に分ける（CPU で 2 分強）→ audio/stems/[曲名]/
$VPY $S/align.py [曲名]       # 歌詞を歌声に時刻合わせ（初回はモデル 1.5GB を落とす）→ work/anatomy/[曲名]/
$VPY $S/extract.py [曲名]     # データを取り出す → songs/analysis/anatomy/[曲名]/
```

**`align.py` が出す行ごとの時刻を、必ず目で見る。**外れ方には型がある。

| 見え方 | 起きていること | 直し方 |
| --- | --- | --- |
| 1 行だけ 10 秒以上ある／0.5 秒も無い | 長い間奏をまたいで、行が間奏の前か後ろに押しつけられた | 下の「やり直し」 |
| 同じ構成（1 番と 2 番の B メロ、サビどうし）の長さが揃わない | 同上 | 同上 |
| 行の頭や終わりが、歌の無い所まで伸びている | 時刻合わせの癖 | `extract.py` が自動で直す（元の値は `start_aligned`・`end_aligned` に残る） |

やり直しは、外れた行だけを、その行が入っているはずの秒の範囲に絞って行う。範囲は、`extract.py` を一度回して
`series/vocal_presence.csv` でボーカルが鳴っている区間を見て決める。

```bash
$VPY $S/align.py [曲名] --lines 35 40 --window 99 114.14   # 歌詞ファイルの 35〜40 行目を、99〜114.14 秒の中でやり直す
$VPY $S/extract.py [曲名]
```

範囲を決めたのは人なので、**やり直した行はオーナーの耳での確認が要る**（`anatomy.json` の `realigned_window` が目印）。

## 手順 B: 場面を選ぶ・色を決める（人。ここが型の中心）

`extract.py` の出力（区間ごとの楽器の平均音量）と `series/stem_loudness.csv` を 1 秒ごとに見て、**6 つ**選ぶ。探す場所:

- **楽器が入る・抜ける所**（歌い出しでベースが無い、落ちサビでドラムが消える）
- **1 回だけ起きる切れ目**（2 回目のサビの前だけベースが消える、など。ほかの回には無いことも確かめる）
- **声の広がりが変わる行**（`lines[].vocal_width`。掛け声が広い、落ちサビが狭い、サビの最後の行だけ狭い）
- **いちばん長い歌の無い所**
- **サビの回ごとに変わる言葉**（「私が」→「君が」→「みんなが」）
- **構成の変わった所**（3 回目の B メロ、歌から始まる、2 番に B メロが無い）

選び方:

- 時間順に並べて、曲の前半・後半に偏らせない（図では時間順に上・下・上…と置かれる）
- 題（`headline`）は**音と歌詞の関係を一言で**。離れている曲は食い違い（「踊れる音に、自分への問いを乗せた曲」）、
  近い曲は同じ向き（「騒いでほしい、を音でも言っている曲」）。離れ具合は `song_character.md` にある
- 既存の歌詞考察（`articles/歌詞考察/[曲名].md`）の読みと食い違わないか見る。使える読みは引く

**曲の色は、図を作る前に必ずオーナーに聞く**（オーナー指示・2026-10-02）。

- 曲の印象に合う候補を 3 つ、色の名前・16 進の値・理由を付けて出し、選んでもらう
- 候補は、図の中の色（サビのピンク `#d6006e`、ベースの青 `#2a6fd6`、その他の楽器の緑 `#1a9a8a`）と近すぎないものにする
- メンバーカラーは使わない（`design.md`: 装飾専用。曲の色と取り違える）
- 色は背景にごく薄く（6%）と、曲名の下線に使うだけ。**図の配色を変えるほど派手にしない**

## 手順 C: 文面を書く

[`story_template.json`](./story_template.json) を `songs/analysis/anatomy/[曲名]/story.json` に写して書く。
項目と `checks` の書き方は [`songs/analysis/anatomy/README.md`](../../../songs/analysis/anatomy/README.md)。

- **「音」（`fact`）は、`checks` で確かめられることだけを書く。**確かめられないことは事実の欄に書かない。
  音の説明の言葉（シンセ、ブラスなど）は `song_character.md` の確認済みの説明だけ
- **「読み」（`reading`）は断定しない。**「〜に聞こえます」「〜と読めます」「〜のように見えます」。
  **作り手の意図として書かない**（インタビューなどの一次情報が無い。`articles/歌詞考察/考察の観点.md` の「因果を書かない」）
- 書かないこと: BPM・キー、未確認の転調、誰が何人で歌っているか、評価語、運営の意図。
  線引きの正は [`songs/analysis/README.md`](../../../songs/analysis/README.md)
- 声の広がりは人数ではない。「大勢の声／一人の声」は読みの側に置く
- 歌詞の引用は短く。`line_no` と表記が歌詞ファイルと一字でも違うと、図は作られない
- 初心者が読む。A メロ・サビなどの言葉は `glossary` で一行説明する。文体は `prompts/write/style_ai_poppar.md`

## 手順 D: 図を作る

```bash
python $S/build_story.py [曲名] --check   # 文面とデータ・歌詞の突き合わせだけ
python $S/build_story.py [曲名]           # 図 → songs/analysis/anatomy/[曲名]/読み解き図.png
python $S/build_anatomy.py [曲名]         # データをそのまま並べた図 → 解剖図.png
python $S/build_table.py [曲名]           # 歌割り表.md（「誰が歌っているか」は空欄）
python $S/build_check.py [曲名]           # 聴きながら確かめるページ → work/anatomy/[曲名]/check.html
```

- 突き合わせが 1 つでも合わないと、図を作らずに止まる。**データに合わせて文面を直す**（突き合わせのほうを緩めない）
- **PNG を必ず自分で開いて見る。**線が解説の枠から外れていないか、文字が重なっていないか、
  歌の無い所の薄い灰色が背景に沈んでいないか

## 手順 E: オーナーに確認してもらう

渡すもの: `読み解き図.png`、`work/anatomy/[曲名]/check.html`（図をクリックするとその位置から再生。PC 専用）、`歌割り表.md`。

聞くこと:

1. 構成の境目は合っているか（特に `realigned_window` の付いた行）
2. 6 つの読みのうち、違うと感じるもの
3. 「大勢／一人」の読みは、実際の歌割りと合うか

訂正は `owner_check.json`（時刻・構成・歌割り）と `story.json`（文面）に書いて、手順 D をやり直す。
確認が済んだら `story.json` の `status` を `owner_confirmed（日付）` にする。
**確認前の図と文面を、記事・動画に使わない。**

## やってみて分かったこと（2026-10-02・2 曲）

- **曲全体の音量では何も見えないが、楽器ごとに分けると展開が見える。**音圧の高い音源でも、落ちサビでドラムとベースが消える・
  歌い出しでベースが無い、といった出入りがはっきり出る
- **音と歌詞が近い曲でも型は成り立つ。**シーソーゲーム（離れている）は「食い違い」、ろりぽっぷ!!!!!!!（近い）は「同じ向き」が題になった
- **時刻合わせは長い間奏をまたぐと外れる。**ろりぽっぷ!!!!!!! は 30 秒の間奏のあとの B メロを間奏の頭に置き、
  次の行を 25 秒に引き伸ばした。やり直したら、B メロが 1 番と同じ約 10 秒に収まった
- **突き合わせが文面の間違いを止める。**「ベースが 0:27 まで鳴っていない」と書いたら、データでは 0:27 が境目で止まった。
  秒単位の事実は、書いた本人の読み違いが入る
- **声の広がり（side/mid）は、2 つにきれいには分かれない。**掛け声がいちばん広く、落ちサビや歌い出しが狭い、という傾向は出る。
  人数や誰の声かは分からない
- **最後のサビの転調は、この方法では 2 曲とも「なし」と出た。**耳での確認はまだ。未確認のまま図に書かない
- **色つきの背景では、白に近い薄い色が沈む。**歌の無い所は、墨を薄く重ねる色にしてある
- 図にして見せると、訂正も注文も出る（縦長 → 横長、番号 → 線、曲名を大きく、曲の色）。**まず 1 枚出す**
- 手元の CPU で足りる。GCP は準備のほうが長い。12 曲まとめて回すなら、専用環境の torch を GPU 版に入れ替える

## 注意

- **音源と分離した音を絶対にコミットしない。**`.gitignore` で除外済み。`git add -f` をしない
- **確認ページ（`check.html`）を公開しない。**購入した音源を読む。Cloudflare などに上げる案は、オーナー判断で見送った（2026-10-02）
- `songs/call_list.md` には依存しない（オーナーが手で修正中。`CLAUDE.md`）。コールの有無を事実として書かない
- スクリプトは `__file__` からの相対でパスを決める。置き場所を動かしたら `common.py` の `ROOT` の階層数を直す
- 図のスクリプト（`build_*.py`）は `common.py` と Playwright だけで動く。重いライブラリを足さない（クラウドで図を作り直せなくなる）

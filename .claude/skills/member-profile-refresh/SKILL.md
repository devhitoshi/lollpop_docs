# メンバーのパーソナリティデータ更新

`members/*.md` の「X の発信傾向」は 2026年3月時点の Grok 分析が元で、卒業や新体制で古くなる。
このスキルは、取得済みの投稿を**数えてから読む**ことで、根拠の無い人物像を書かないようにする。

## 前提

- `work/x_fetch/<handle>.jsonl` に対象期間の投稿があること（無ければ `.claude/skills/x-account-fetch` で取得。1ヶ月・5人で 600〜800件、$0.1 程度）
- 期間は 1〜3ヶ月が目安。短すぎると定型句が拾えず、長すぎると古い傾向が混ざる

## 手順

1. **数える**

   ```bash
   python3 .claude/skills/member-profile-refresh/scripts/profile_stats.py --since 2026-08-01 --until 2026-08-31
   ```

   `work/x_fetch/profile_stats_<since>_<until>.md` に、メンバーごとの投稿数・時間帯・曜日・ハッシュタグ・絵文字・メンション先・冒頭と末尾の定型句・よく出る語・伸びた投稿5件が出る。
   未取得のメンバーは「未取得」と出る。**5人の扱いを揃える**ため、揃うまで更新を見送るか、揃っている範囲だけ更新して README の未解決に書く。

2. **読む**

   統計で目についた項目（新しい定型句、増えたハッシュタグ、時間帯の変化）について、`<handle>.jsonl` の原文を検索して確かめる。
   統計は「2〜4文字の連続」の簡易集計なので、語の切れ目が変なことがある。原文で裏を取っていないものは書かない。

3. **書く**（`members/<ローマ字名>.md`）

   - 更新するのは「X の発信傾向」の節（発信の軸・価値観・文体・主な読み手）と、基本情報のハッシュタグ・プロフィール文
   - 節の冒頭の出典行を書き換える: `> 出典: 取得した投稿の集計（YYYY-MM-DD〜YYYY-MM-DD・N件、.claude/skills/member-profile-refresh）`
   - 割合（「告知 約40%」）を書くなら、統計の数から出す。感覚で書かない
   - **書かないこと**: 体調・私生活・人間関係の推測、運営の意図、卒業メンバーの卒業後
   - 文体の特徴（伸ばし棒、記号の重ね方、絵文字）は統計の絵文字上位・末尾の定型句から拾える。例文は原文から1〜2個

4. **確認する**

   `members/README.md` の一覧（あだ名・担当カラー・X）と `members/members.md` に矛盾が無いか見る。
   `article-review` の機械チェックは members.md を正として絵文字を照合するので、担当カラーを変えるときは members.md を先に直す。

## 出力の扱い

`profile_stats_*.md` と JSONL は他人の投稿原文を含む。`work/x_fetch/` に置いたまま、コミットしない。
リポジトリに入るのは、根拠を要約した `members/*.md` の記述だけ。

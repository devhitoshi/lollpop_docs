# 週刊・月刊まとめの下書き

収集（x-account-fetch）→ 素材化（このスキルのスクリプト）→ 執筆（prompts/write/ に従う）→ レビュー（article-review）→ README 更新、を一本でつなぐ。
文体と構成の正は `prompts/write/` にある。このスキルはそれを置き換えず、**読む順番と手順**を決めるもの。

## 前提

- `work/x_fetch/` に期間をカバーする公式・メンバーの投稿（JSONL）があること。無ければ先に `.claude/skills/x-account-fetch` で取得する
  （twitterapi.io に到達できない環境では、ユーザーに Grok の収集結果を貼ってもらい、素材ファイルの代わりに使う）
- `events/data_event.csv` に期間内の公演が入っていること。抜けは素材化のときに「CSV に無い公演の疑い」として出るので、先に CSV を直す

## 手順

1. **期間とファイル名を決める**

   | 種別 | 期間 | 記事の置き場 | 読者 |
   | --- | --- | --- | --- |
   | 週刊 | 火曜〜月曜（`articles/週刊まとめ/README.md` の「週の区切り」に従う） | `articles/週刊まとめ/YYYY-MM-DD_YYYY-MM-DD.md` | すでに知っている人 |
   | 月刊 | 1日〜月末 | `articles/月刊まとめ/YYYY-MM.md` | ほとんど知らない人 |

2. **素材ファイルを組み立てる**

   ```bash
   python3 .claude/skills/weekly-monthly-draft/scripts/build_material.py --since YYYY-MM-DD --until YYYY-MM-DD [--type monthly]
   ```

   `work/x_fetch/draft_material_<since>_<until>.md` ができる。`x_collect.md` の出力形式に寄せてあり、
   公演ごとの CSV セトリ＋公式のライブ後投稿、新曲・告知の候補、メンバーの投稿（原文・全件）、今後の予定の候補、取得状況が入る。
   **これを最初から最後まで読む。** 記事に書く事実はこのファイル（と CSV）にあるものだけ。
   「取得状況」に未取得のアカウントがあれば、そのメンバーだけ扱いが薄くなる。5人の扱いが不均衡になるなら、その節は見送って README の未解決に書く（前号の判断と同じ）。

3. **必読ファイル**（毎回。省略しない）

   - `prompts/write/style_ai_poppar.md` … 文体
   - `prompts/write/weekly.md` または `prompts/write/monthly.md` … 構成・読者・軸の決め方
   - `articles/<シリーズ>/README.md` … 運用方針、未解決、前号の判断
   - 前号の記事 … 文体と構成の継続性。同じ言い回しを繰り返さないためにも読む
   - 月刊のみ: `members/members.md` と各メンバーの `members/*.md`（メンバー紹介の「その人らしさ」は投稿と人物データに根拠がある範囲だけ）

4. **書く**

   - 構成は prompts/write/ のテンプレートどおり。ただし **note の制約が優先**: 表組みは使わない（「来週の予定」「ライブに行ってみるには」は箇条書き）、見出しは `#` と `##` の2階層まで
   - 週の軸（月刊は月を象徴する出来事）を1つ決めてリード文で名指しする。無理に作らない
   - 事実（日時・会場・料金・セトリ）は素の箇条書き。感想はそのあとに1〜3文
   - 曲名・イベント名は素材の表記ママ。「!」の数・「☆」「★」・「〜」「～」を揃えない
   - 「現場の反応」「外からの反応」はエゴサーチの結果が無ければ、節を**省略せず**「（エゴサーチ未実施。結果が揃い次第追記）」と1行書く。未解決にも載せる
   - 出典節は素材の URL から、本文で使ったものだけを日付順に
   - 末尾に `---` で区切って編集メモ（確認できなかった項目・判断に迷った点・拾いきれなかった領域）。素の口調で

5. **レビューして直す**

   `.claude/skills/article-review` の手順（機械チェック → article-review エージェント）を通し、必須修正を反映する。

6. **README を更新する**

   `articles/<シリーズ>/README.md` の記事一覧に1行追加し、未解決の節を更新する（`.claude/skills/session-handoff` の書き方）。

7. **コミットするもの・しないもの**

   - コミットする: 記事、README、CSV の修正
   - コミットしない: `work/x_fetch/` の素材ファイルと JSONL（他人の投稿原文。`.gitignore` 済み）

## 注意

- 素材に無いことは書かない。話をつなぐための推測で埋めない。分からないことは編集メモへ
- 卒業メンバーは在籍時の事実だけ。卒業後の活動・私生活には触れない
- 数字（動員・売上）の評価、他グループとの比較、運営の判断、体調・人間関係の推測、煽りは書かない
- 「公演数」を書くときは CSV の期間内の行数と一致させる（機械チェックが照合する）

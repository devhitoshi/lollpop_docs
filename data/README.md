# 収集データの置き場

Grok から受け取った収集データをここに積み上げます。
`prompts/x_collect.md` で集めたものを、後から軸を変えて振り返れる形にしておくためのディレクトリです。

## 構成

```
data/
├── INDEX.md          … 索引（生成物）。まずここを見る
├── collected/        … Grok から受け取った原本。手で書き換えない
│   └── 20260801-20260831/
│       ├── 20260801-20260815.md   … チャンクごとの受信データ（そのまま）
│       ├── 20260816-20260831.md
│       ├── 20260816-20260831.csv  … event_get.md の返り値（あれば）
│       ├── merged.md              … 結合済み。派生ファイルはこれから作る
│       └── meta.json              … 期間・チャンク構成・取り込み日時
├── events/           … イベントごと（生成物）
│   └── 2026/2026-08-26_単独ライブ（2部_Vol.18_夏曲お披露目公演）.md
├── members/          … メンバーごと（生成物）
│   └── 愛月まな.md
├── reactions/        … ファンの声、月ごと（生成物）
│   └── 2026-08.md
└── topics/           … 新曲・初披露 / アナウンス・告知、月ごと（生成物）
    └── 2026-08.md
```

## 原本と生成物

**`collected/` だけが原本**です。Grok は同じ期間を投げ直しても同じ結果を返さないので、
受け取った出力はそのまま残します。手を入れたくなったら原本を直してください。

**それ以外は毎回まるごと作り直される生成物**です。直接編集しても次の再構築で消えます。
一度消してから組み直しているので、原本から消えた項目が残り続けることはありません。

```bash
# work/collect/ の受信データを取り込んで、軸別ファイルを作り直す
python3 .agent/scripts/archive_collect.py --period 20260801-20260831

# 取り込みはせず、collected/ から作り直すだけ
python3 .agent/scripts/archive_collect.py --rebuild
```

`--rebuild` は何度実行しても同じ結果になります。

## 軸について

| 軸 | 場所 | 元にしている節 |
|---|---|---|
| 全体（期間ごと） | `collected/<期間>/merged.md` | すべて |
| イベントごと | `events/<年>/` | `## ライブ・イベント` |
| メンバーごと | `members/` | `## メンバーの投稿` |
| ファンの声 | `reactions/` | `## 外部の反応` |
| 新曲・アナウンス | `topics/` | `## 新曲・初披露` `## アナウンス・告知` |

イベントのファイルには、`data_event.csv` に同じ日付・イベント名の行があればセトリも一緒に載せます。
収集データ側のセトリは Grok が読んだ時点のもの、`data_event.csv` 側が確定版という位置づけです。

メンバーの対応づけは `prompts/x_collect.md` の収集対象アカウント（`@handle` の一覧）を見ています。
突き合わせられなかった見出しは `members/_未対応/` に落ちて、実行時に警告が出ます。
メンバーが増減したときは `prompts/x_collect.md` を先に直してください。

## 注意

`## 確認できなかった項目` と `## 判断に迷った点` は軸別ファイルには展開していません。
どの期間の話か分からなくなると使えなくなるので、`collected/<期間>/merged.md` の中だけに残しています。

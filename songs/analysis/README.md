# 曲調データ

各曲の音の側のデータです。`songs/lyrics/` の歌詞と対になります。
**手書きではなく、スキル `music-analysis` が作ります。**

2 種類あります。

| 種類 | 何が分かるか | 信用度 |
| --- | --- | --- |
| **曲の印象**（`song_character.md`） | かわいいのか・かっこいいのか、湧き曲か・エモい曲か、歌詞と音が合っているか | AI が聴いた採点を、オーナーが耳で確かめたもの。**記事に使える** |
| **数値**（`[曲名].md`、`song_features.csv`） | 尺、BPM、キー、区間ごとの音量 | BPM とキーは確定できていない**参考値**。記事には書かない |

## ファイル

| パス | 内容 |
| --- | --- |
| `song_character.md` | 曲の印象の一覧。音の位置、確認済みの説明、音と歌詞の離れ具合（自動生成） |
| `song_character.csv` | 上の位置の数値。図を作るときに読む |
| `character/owner_check.json` | AI の 2 回の説明が食い違った曲について、オーナーがどちらが近いかを答えた記録。**ここだけは人が書く** |
| `character/lyrics_scores.json` | 歌詞だけを読んで付けた採点と根拠 |
| `character/raw/` | AI（Antigravity）の採点の生データ。**未確認の説明を含む。ここから直接記事に引かない** |
| `[曲名].md` | 1 曲分の数値。尺・BPM（参考値）・キー（参考値）・区間ごとの音量 |
| `song_features.csv` | 全曲比較用の数値 |
| `anatomy/[曲名]/` | 曲を楽器ごとに分けた解剖データと、読み解き図（スキル `song-anatomy`）。項目は [`anatomy/README.md`](./anatomy/README.md) |

作り方は [`.claude/skills/music-analysis/SKILL.md`](../../.claude/skills/music-analysis/SKILL.md) にあります。
`anatomy/` だけは [`.claude/skills/song-anatomy/SKILL.md`](../../.claude/skills/song-anatomy/SKILL.md) です。

## 記事で書いてよい範囲

オーナー決定（2026-10-01）。**この節が正です。**

書いてよい:

- **`song_character.md` で状態が「確認済み」の曲の、位置と「確認済みの説明」。**
  例: 「主人公はピアノとストリングスが主役の曲で」「Unknown は 12 曲でいちばんかっこよくて攻撃的なサウンド」
- **状態が「2回一致」の曲の、位置。** 例: 「メイク☆マイダンスはかわいくて湧く側の曲」。
  楽器や歌い方の説明は、オーナーに確かめてから書く
- **音と歌詞の離れ具合。** 例: 「シーソーゲームは、内省的な歌詞を湧き寄りの音に乗せている」。
  歌詞の側は読み手（AI）の解釈なので、解釈として書く

書かない:

- **AI が外した説明を、事実として書くこと。** 「AI はこう聴き間違えた」という失敗の例として紹介するのはよい
  （`articles/単発/18_12曲の地図/note.md` がその例。2026-10-01）
- **AI の説明のうち、オーナーが確認していない部分**（`character/raw/` にある楽器名・ジャンル名・時刻つきの展開）。
  オーナーが確かめた曲では、少なくとも片方の回は近かったが、**どちらの回も 1 曲以上で外している**
  （「シーソーゲームは重低音ギターのラウドロック」「未完成ヒロインはいちばんゆったりしたバラード」など。`song_character.md` に一覧あり）
- **BPM とキーの数値。** 同じ曲で 172 と 117 が出るなど、確定できていない。曲中でリズムの刻みや調が変わる曲が多く、
  1 曲に 1 つの値を付けること自体が合っていない
- **位置の数値そのもの**（「+2.6」など）。印象の採点であって測定値ではない。「かっこいい寄り」のように言葉で書く

読み解き図（`anatomy/[曲名]/`）から書くとき（2026-10-02 追加）:

- **`story.json` の `status` が `owner_confirmed` になった曲だけ使う。**確認前の図と文面は、記事・動画に使わない
- **「音」の欄（`fact`）は書いてよい。**楽器が入る・抜ける時刻、歌の無い長さなど、データと突き合わせた事実。
  例: 「落ちサビではドラムとベースが消える」。秒数は「約 7 秒」のように丸めて書く
- **「読み」の欄（`reading`）は解釈として書く。**「〜に聞こえる」「〜と読める」。作り手の意図として書かない
- **声の広がりを、人数や歌割りとして書かない。**測っているのは左右への広がりだけ
- **転調は、オーナーが耳で確かめたものだけ書く。**機械の判定（`anatomy.json` の `modulation`）だけでは書かない

書くときの作法:

- 断定を避ける必要はないが、**出どころを記事末の「データの出どころ」に書く**
  （例: 「曲の印象: songs/analysis/song_character.md（AI が聴いた採点をオーナーが確認・2026年10月1日時点）」）
- 評価語を足さない。「かっこいい」「エモい」は位置を表す言葉として使い、曲の優劣には使わない
  （[`articles/歌詞考察/考察の観点.md`](../../articles/歌詞考察/考察の観点.md) F 節）

## 読むときの注意

- **「湧き ↔ エモい」は現場の反応の話**で、音だけでは決まらない。AI の採点よりオーナーの実感を優先する
- **AI は全曲を「速い」「疾走感」と評しがち。** テンポ感についての AI の言葉は、聴き比べの順位（`character/raw/_ranking.json` の `tempo_rank`）も含めて未確認
- **曲の位置は 12 曲の中での相対的なもの。** 新曲を足すときは、全曲の聴き比べ（`rank_agy.py`）を取り直す
- 数値の側の注意（BPM の倍・半分、キーの平行調、機械的なセクション境界）は、各 `[曲名].md` の末尾に書いてある

## これまでに分かっていること（2026-10-01）

- 12 曲は「かわいい・湧き」（6 曲）と「かっこいい・エモい」（3 曲）に大きく分かれる
- 音と歌詞がいちばん離れているのは「シーソーゲーム」。次が「夏色ラムネ」
- 軸の候補のうち、「盛り上がる ↔ 魅せる」は「湧き ↔ エモい」と、「明るい ↔ 暗い」は「かわいい ↔ かっこいい」と、ほぼ同じ並びになった。
  「穏やか ↔ 激しい」は全曲が激しい側で差が出なかった。そのため 2 軸は「かわいい ↔ かっこいい」×「湧き ↔ エモい」にしている
